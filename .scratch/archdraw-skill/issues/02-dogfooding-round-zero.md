# 02: 도그푸딩 — 다 만든 뒤 실제 업무에서 써보고 이슈로 남긴다

**What to build:** 코드가 아니라 관찰 기록. **01·03~07을 다 만든 뒤**(2026-09-14 그릴 확정 — 구 "규칙 쓰기 전 0바퀴" 폐기) 사용자가 회사·개인 프로젝트에서 스킬을 실제로 쓴다. 스펙의 판단 규칙은 대부분 실사용 없이 조립한 가설이므로(스펙 Further Notes), 규칙의 유지·수정·제거는 **모인 이슈를 보고 사용자가 판단**한다(횟수 기준 없음 — 2026-09-14 그릴, 구 "세 번 이상 교정" 폐기). 판정 결과는 03~07 해당 이슈에 수정 사항으로 되돌아간다.

돌려볼 것:
- 줌 레벨 드릴다운: 시스템 컨텍스트 → 배포 단위 → 모듈 경계. 각 레벨에 금지된 디테일이 섞이는지.
- 의존 도달 범위 색칠: 기존 그림 위에 "나를 쓰는 쪽 / 내가 쓰는 쪽"을 칠하게 시켜본다.
- 캔버스 직접 수정: 사용자가 박스를 옮기고, 사용자 표시를 남기고, 초안(손그림·사진)을 던진다. 에이전트가 뒤엎는지.
- 설명 그림 vs 도면: "다듬어줘"·"저장해"가 자연스러운지. 이건 그려봐야 아는 유일한 미검증 항목이다.
- Codex 실동작: 같은 발화를 Codex에서 돌려 Claude와 다른 지점.
- 대화 중 사용: 정방향(에이전트 설명이 이해 안 됨 → 그림)·역방향(`네가 이해한 대로 그려봐` → 캔버스에서 고침). Claude·Codex에서 한 번 명시 호출한 뒤 "그럼 결제 실패하면?"처럼 연결·순서를 묻는 후속 발화에 재호출 없이 그림으로 이어 답하는지 확인한다(검수 R11). 압축 후 재호출·재개와 "텍스트로 답해"가 규칙 없이 먹히는지도 관찰한다. 호스트별 결과와 재호출 필요 여부를 기록하며, 실제로 안 쓴 호스트는 미시험으로 남긴다. API 계약 행(표준 없는 근사형)은 최우선 시험.
- 좌표 공식(09): 에이전트가 열·행 공식으로 찍은 그림에서 겹침·선 엉킴이 반복되는지. 반복되면 서버가 (열, 행)을 받아 배치하는 승격을 별도 이슈로 연다(2026-09-19 그릴 Q1 (c)).
- 열·행 방향(09): 그림 종류별 열·행 의미(시퀀스 열=참여자·행=시간, 구조도 행=층 등)와 가로 시간축 그림(타임라인·레인 타임라인·워터폴)의 공식 예외는 적지 않았다(2026-09-20 그릴 Q3 (c), drawio도 안 적음). 에이전트가 그림을 눕히거나 시간축을 격자에 억지로 넣으면 그때 03 라우팅 표에 그림 종류별 한 줄을 추가한다.
- 글꼴: 서버 기본 Helvetica로 영어·한글 라벨이 읽히는지(한글은 대체 글꼴이라는 추측).

기록 방법(2026-09-14 6차 그릴 확정): 도그푸딩은 다른 PC(회사·개인 프로젝트)에서 돌린다. 코드는 옮기지 않고 **사용자 요구사항만** 이 레포 GitHub Issues에 `dogfooding` 라벨로 한 건씩 쓴다 — 발화 · 나온 그림 · 불만/고친 것 · 원했던 것. 쓰는 일은 [08 기록 스킬](08-dogfooding-report-skill.md)이 대신한다(2026-09-19 2차 검수 B). 레포가 공개라 회사명·클래스명·테이블명은 쓰지 않는다. 기능이 아니라 운영 방식이다(코드 0줄). 모이면 이 디렉터리 `dogfooding-00.md`로 정리하고, 항목마다 사용자 판정(유지·수정·제거)과 이유 한 줄을 적는다. 라우팅 21행은 프로젝트 하나로 못 돌린다 — **걸린 행만 재판정**하고 안 걸린 행은 "미시험"으로 표시해 확정 초안 그대로 둔다(다음 바퀴에서 재판정).

## 검증 결과 정리 (R10)

기존 발화·나온 그림·불만/고친 것·원했던 것 기록을 바탕으로, 의미 문제(질문·그림 종류·레벨·필수요소)와 화면 문제(글자 잘림·겹침·탐색 동작)를 구분해 정리한다. 사용자가 규칙의 유지·수정·제거를 판단하는 방식은 그대로다. 공개 이슈에 회사 코드나 화면 원본을 올리는 요구는 추가하지 않는다.

- [ ] 시험한 항목의 의미 평가와 화면 확인 결과가 구분돼 있고, 확인하지 않은 부분은 미시험으로 남겼다.
- [ ] 도그푸딩에서 확인한 사례와 기대 결과를 03의 후속 with/without 비교에 전달했다. 비교 eval 완료를 02 착수 조건으로 삼지 않는다.

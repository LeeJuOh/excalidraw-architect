# 02: 도그푸딩 0바퀴 — 규칙을 쓰기 전에 손으로 돌린다

**What to build:** 코드가 아니라 관찰 기록. 01로 설치한 골격 위에서, 실제 백엔드 프로젝트 하나를 골라 사용자가 에이전트와 직접 그림을 주고받는다. 스펙의 판단 규칙은 대부분 실사용 없이 조립한 가설이므로(스펙 Further Notes), **세 번 이상 반복해서 교정한 것**만 규칙 후보로 남긴다. 03은 이 기록을 입력으로 쓴다.

돌려볼 것:
- 줌 레벨 드릴다운: 시스템 컨텍스트 → 배포 단위 → 모듈 경계. 각 레벨에 금지된 디테일이 섞이는지.
- 의존 도달 범위 색칠: 기존 그림 위에 "나를 쓰는 쪽 / 내가 쓰는 쪽"을 칠하게 시켜본다.
- 캔버스 직접 수정: 사용자가 박스를 옮기고, 사용자 표시를 남기고, 초안(손그림·사진)을 던진다. 에이전트가 뒤엎는지.
- 설명 그림 vs 도면: "다듬어줘"·"저장해"가 자연스러운지. 이건 그려봐야 아는 유일한 미검증 항목이다.
- frame: 캔버스가 frame 요소를 프론트 수정 없이 그리는지(05의 전제).
- Codex 실동작: 같은 발화를 Codex에서 돌려 Claude와 다른 지점.

기록은 이 디렉터리에 `dogfooding-00.md` 하나로 남긴다. 항목마다 "몇 번 교정했나 / 규칙으로 남길까"를 적는다.

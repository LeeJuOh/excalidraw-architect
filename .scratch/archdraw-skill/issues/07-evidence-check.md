# 07: 근거 검사 — 에이전트가 `코드` 근거를 적으면 서버가 확인하고, 틀리면 거부한다

> 02 도그푸딩(구현 뒤)의 판정이 수정 사항으로 돌아온다. 2026-10-11 그릴로 "틀리면 점선 강등"을 "틀리면 거부"로 바꿨다([ADR-0005](../../../docs/adr/0005-server-checks-evidence-and-demotes.md) 개정).

**What to build:** 에이전트가 선·박스·값에 근거 태그를 붙여 그린다. `코드` 태그는 파일 경로와 그 파일의 코드 글자(`quote`)를 적는다. 에이전트가 근거를 적거나 고칠 때, 서버는 그 글자가 지금 프로젝트의 그 파일 안에 정확히 한 곳 있는지 확인한다. 없거나 여러 곳이면 그 쓰기를 거부하고, 에이전트가 고치는 길을 에러로 알려 준다. 서버는 그림의 모양을 바꾸지 않는다. `설계`·`로그` 태그는 검사 없이 기록만 한다. 근거 태그는 캔버스에 보이지 않는 요소 데이터다 — 서버와 `describe`만 읽는다. 의미(정말 그 의존성인지)는 검사하지 않는다 — 의미 판단은 에이전트, 글자 존재 확인은 서버.

**Blocked by:** 01 (플러그인 골격), 04 (캔버스 세션의 프로젝트 루트 — 근거 경로를 푸는 기준)

**Status:** ready-for-agent

## 결정 (2026-10-11 그릴)

1. 그릴 때 `코드` 근거가 근거 없음이면 **거부**한다. 점선 강등, "서버 강등" 표시, 선을 따라다니는 근거 없음 텍스트는 없다.
2. 검사는 에이전트가 근거를 적거나 고치는 쓰기에서만 한다(요청에 `evidence`가 있을 때). 위치·색만 바꾸는 쓰기와 브라우저 sync는 검사하지 않는다.
3. 한 묶음(batch)에서 하나라도 틀리면 전부 거부하고, 틀린 것을 모두 나열한다. frame 검사(05)와 같은 방식이다.
4. `코드` 근거 = `path` + `quote`(둘 다 필수). `quote`는 파일 안에서 한 곳이어야 한다. 공백(탭·공백·줄바꿈) 차이는 무시한다. 줄 번호와 커밋 SHA는 없다 — 지금 파일이 기준이다.
5. `path`는 프로젝트 루트 기준 상대 경로다. 루트 밖(`..`, 절대 경로)과 `.git`은 거부한다(archify 규칙).
6. 서버는 선·박스의 모양을 바꾸지 않는다. 추론 점선에 유효한 근거가 붙어도 점선 그대로다.
7. 복원·import는 거부하지 않는다. 받아들이고 근거 없음 요소의 목록을 돌려준다. 그림은 바꾸지 않는다.
8. 복원 뒤 목록을 받은 에이전트: 같은 코드를 다른 곳에서 찾으면 근거를 고치고 사용자에게 알린다. 찾지 못하면 그 관계가 코드에서 없어졌는지 사용자에게 묻는다(스킬 규칙).
9. 거부 에러의 고치는 길은 두 개만 적는다: 맞는 `quote`로 고치기 / 확인하지 못하면 `코드` 근거를 빼고 추론 점선으로 그리기. `설계`로 바꾸라고는 적지 않는다.

남는 위험 2개(관계없는 글자를 베껴 통과, 복원 뒤 에이전트가 목록을 알리지 않음)는 02에서 관찰한다.

## 슬라이스 A — 그릴 때 검사와 거부

**What to build:** 에이전트가 MCP나 CLI로 `코드` 근거를 붙여 그리거나 고치면 서버가 검사한다. 틀리면 아무것도 만들거나 바꾸지 않고 거부한다. 스킬 글과 그리기 규격도 같은 커밋에서 거부 기준으로 고친다 — 서버가 `quote`를 검사하기 전에 스킬이 `quote`를 쓰라고 하면 서로 맞지 않기 때문이다.

**Blocked by:** 없음

**Status:** ready-for-agent

- [ ] 파일 안에 한 곳 있는 `quote`로 `코드` 태그 화살표를 만들면 그린 그대로 생긴다
- [ ] 파일이 없거나 `quote`가 파일에 없으면 거부되고 요소가 생기지 않는다. 에러에는 요소, 경로, `quote`, 이유, 그리고 고치는 길 두 개(맞는 `quote` / `코드` 근거를 빼고 추론 점선)가 있다. `설계` 안내는 없다
- [ ] `quote`가 파일에 여러 번 나오면 거부되고, 에러에 나온 횟수와 "한 곳으로 좁혀라"가 있다. 바로 옆 글자를 붙여 한 곳으로 좁히면 통과한다
- [ ] 탭·공백·줄바꿈만 다른 `quote`도 찾는다. 여러 줄 `quote`도 찾는다
- [ ] `코드` 태그에 `path`나 `quote`가 없거나, 태그가 3종 밖이거나, 값의 타입이 틀리면 거부된다
- [ ] 절대 경로, `..`, `.git`을 가리키는 `path`는 거부된다. 프로젝트 루트 밖을 가리키는 심볼릭 링크도 거부된다
- [ ] batch에서 하나라도 틀리면 아무것도 생기지 않고, 틀린 것이 모두 나열된다
- [ ] 화살표의 `evidence`를 틀린 값으로 `update`하면 거부되고 요소는 이전 그대로다. `evidence` 없이 위치만 `update`하면 검사하지 않는다(근거 파일이 그 사이 바뀌었어도 통과)
- [ ] `코드` 태그 박스도 같은 규칙으로 검사된다
- [ ] 서버는 모양을 바꾸지 않는다: 추론 점선 + 추론 라벨에 유효한 근거를 붙여도 점선과 라벨이 그대로다
- [ ] 파일에 있는 글자지만 그림의 관계와 무관해도 통과한다 — 서버는 의미를 판단하지 않는다
- [ ] `설계`·`로그` 태그는 검사 없이 통과하고 `describe`에 태그가 보이며, 캔버스 스크린샷에는 태그 텍스트가 없다
- [ ] 태그 없는 요소는 업스트림과 동일하게 동작한다(하위 호환)
- [ ] MCP(create/batch/update)와 CLI(`add`/`apply`/`update`)가 같은 결과를 낸다
- [ ] 그리기 규격의 선 표기 표에 근거 검사 실패 행이 없다. 스킬 본문과 조작 가이드의 `evidence` 모양이 `path` + `quote`이고, 근거를 못 찾을 때의 행동이 거부 기준이다(점선으로 둔다, 근거 없음 표시 같은 문장이 없다)
- [ ] 03 슬라이스 B의 근거 인수가 거부 기준으로 바뀌어 있다
- [ ] 기존 `npm test` 통과

## 슬라이스 B — 복원·import 때 근거 없음 목록

**What to build:** 저장한 뒤 코드가 바뀌어 근거 없음이 된 요소가 있어도 `snapshot restore`·`import`는 된다. 결과에 근거 없음 요소의 목록이 나온다. 스킬은 그 목록을 받았을 때의 행동(결정 8)을 안다.

**Blocked by:** 슬라이스 A

**Status:** ready-for-agent

- [ ] 근거 코드를 지운 뒤 `snapshot restore`하면 복원되고, 그림 모양은 그대로이며, 결과에 근거 없음 요소의 목록(요소, 경로, `quote`, 이유)이 있다. 근거가 맞는 요소는 목록에 없다
- [ ] `import`도 같다. 목록의 요소 ID는 import가 새로 발급한 ID다
- [ ] 목록은 결과의 앞부분에 있어 다른 결과에 묻히지 않는다
- [ ] MCP와 CLI가 같은 결과를 낸다
- [ ] 스킬 글에 결정 8이 있다: 같은 코드를 찾으면 고치고 알림, 못 찾으면 사용자에게 물음

## 슬라이스 C — 브라우저 왕복에서 근거 보존

**What to build:** 사용자가 브라우저에서 요소를 만지고 저장·재로드해도 `evidence`가 남는다. sync는 검사하지 않는다. 깨지면 프론트 작업이 이 슬라이스에 추가된다.

**Blocked by:** 슬라이스 A

**Status:** ready-for-agent

- [ ] 브라우저에서 `코드` 태그 화살표를 끌어 옮긴 뒤 `describe`에 `evidence`가 그대로 있다
- [ ] 근거 코드를 지운 상태에서 브라우저로 화살표를 옮겨도 sync가 성공한다(검사하지 않음)
- [ ] 브라우저 탭을 재로드한 뒤에도 `evidence`가 남아 있다

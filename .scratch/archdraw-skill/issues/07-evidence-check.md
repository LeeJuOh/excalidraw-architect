# 07: 근거 검사 — `코드` 태그의 파일:줄을 그릴 때마다 서버가 확인한다

> 02 도그푸딩(구현 뒤)의 판정이 수정 사항으로 돌아온다. 검사 시점(매번 vs 저장 시)은 실사용에서 방해되면 재검토한다.

**What to build:** 에이전트가 선이나 값에 근거 태그를 붙여 그린다. `코드` 태그는 `파일:줄`을 함께 적고, 서버가 그 파일·줄이 실제로 있는지 **그릴 때마다** 확인한다. 파일이 없거나 지정한 줄이 파일 범위 밖이면 그 선은 점선으로 강등되고 캔버스에 근거 없음 텍스트가 자동으로 생긴다(문자열은 `docs/canvas-guide.md` 선 표기 표가 원본, 영어 고정 — [ADR-0012](../../../docs/adr/0012-canvas-labels-fixed-english.md)). `설계`·`로그` 태그는 검사 없이 기록만 한다. 근거 태그는 캔버스에 보이지 않는 요소 데이터다 — 서버와 `describe`만 읽고, 사용자는 점선과 추론·근거 없음 표시를 본다. 의미(정말 의존성인지)는 검사하지 않는다 — 내용의 의미 판단은 에이전트, 파일·줄 존재 확인은 서버. ([ADR-0005](../../../docs/adr/0005-server-checks-evidence-and-demotes.md))

- 요소에 `evidence: {tag: code|design|log, path, line}` 칸 추가.
- 생성 경로(MCP create/batch, CLI `add`/`apply`)가 공유하는 한 곳에 검사를 넣는다. 레포 위치는 세션의 프로젝트 루트(04, 검수 R03 — 구 "서버 cwd").
- 선 표기(검수 R05)는 PRD §3 "선 표기"의 결정을 따르고, 서버가 만들거나 보존하는 라벨 문자열은 `docs/canvas-guide.md` 선 표기 표에서 읽는다(ADR-0012). 강등·복구 시 화살촉과 통신 방식·응답 표시를 보존한다. 에이전트가 붙인 추론 표시도 유지한다.
- 박스 강등(2026-09-20 그릴 Q5 (a), 스토리 33 갭): 박스에도 `코드` 태그가 붙는다(초안 시작 장면). 파일·줄이 없으면 선과 같은 규칙 — 테두리를 점선으로 바꾸고 근거 없음 텍스트(대상은 박스 이름)를 붙인다. 복구·수명주기·"서버 강등" 표시는 아래 선 규칙과 같다. 박스 색·이름은 보존한다.
- 강등은 하되 거부하지 않는다. archify의 거부 루프와 다른 점.
- 에이전트가 처음부터 점선(추론)으로 그린 선은 건드리지 않는다. 서버가 내린 선은 요소에 "서버 강등" 표시를 남기고, 근거가 맞아지면 서버가 실선으로 되돌리며 "근거 없음" 텍스트를 지운다.
- **생성 후 수명주기 (검수 R04, 2026-09-14 그릴 확정):**
  1. `evidence` 칸이 바뀌면 생성·수정(CLI `update`/`apply`, MCP update, 서버 PUT, 브라우저 `POST /api/elements/sync`) 어디서든 같은 검사가 돈다. sync는 메모리 요소를 전체 교체하므로(`src/server.ts` sync 핸들러) 교체 후 "근거 없음" 텍스트의 원본 선이 없으면 그 텍스트도 지운다(2026-09-19 2차 검수 A4).
  2. import·`snapshot restore`로 들어오는 요소도 같은 검사. 저장 뒤 코드가 바뀌어 사라진 근거는 복원 시점에 강등된다. 검사 통과 = 현재 프로젝트의 파일·줄 존재 확인. 의존성의 의미는 보장하지 않는다.
  3. 근거 없음 텍스트는 원본 선 ID를 기억한다. 선이 움직이면 따라가고(라벨처럼 붙임), 선이 삭제되거나 실선 복구되면 서버가 지운다. import 복사(06) 때 ID 재매핑에 포함한다.
  4. 브라우저 왕복(사용자가 요소를 만지고 저장·재로드)에서 `evidence`·"서버 강등" 표시가 보존되는지는 기술 확인 — 깨지면 프론트 작업이 이 이슈에 추가된다.
- SKILL.md의 태그 붙이는 규칙은 03 담당(2026-09-20 이관). 이 이슈는 서버 검사·강등·표시만 한다.

**Blocked by:** 01 (플러그인 골격), 04 (캔버스 세션의 프로젝트 루트 — 근거 경로를 푸는 기준)

**Status:** ready-for-agent

- [ ] 없는 파일이나 범위 밖 줄이면 화살표가 점선이 되고 근거 없음 텍스트가 옆에 생긴다. 텍스트 문자열은 `docs/canvas-guide.md` 선 표기 표의 것과 같다
- [ ] 없는 파일·줄로 `코드` 태그 박스를 만들면 테두리가 점선이 되고 박스 이름을 대상으로 한 근거 없음 텍스트가 옆에 생기며, 있는 줄로 고치면 실선으로 돌아온다
- [ ] `설계`·`로그` 태그는 검사 없이 통과하고 `describe`에 태그가 보이며, 캔버스 스크린샷에는 태그 텍스트가 없다
- [ ] 태그 없는 요소는 업스트림과 동일하게 동작한다(하위 호환)
- [ ] 실선 화살표의 근거를 없는 줄로 `update`하면 점선 + "근거 없음"이 되고, 다시 있는 줄로 고치면 실선으로 돌아오며 텍스트가 사라진다
- [ ] 에이전트가 처음부터 점선으로 그린 화살표에 맞는 근거를 붙여도 서버가 실선으로 올리지 않는다
- [ ] 점선 화살표를 지우면 "근거 없음" 텍스트도 사라지고, 화살표를 옮기면 텍스트가 따라간다
- [ ] 근거 파일을 지운 뒤 `snapshot restore`·`import`하면 그 선만 점선이 되고 나머지는 그대로다
- [ ] 브라우저에서 화살표를 끌어 옮긴 뒤 `describe`에 `evidence`와 "서버 강등" 표시가 남아 있다
- [ ] 브라우저에서 강등된 점선 화살표를 지우면 sync 뒤 "근거 없음" 텍스트도 사라진다. 브라우저에서 화살표를 옮기면 sync 뒤에도 텍스트가 따라간다(2차 검수 A4)
- [ ] 기존 `npm test` 통과

- [ ] 확인된 동기 호출·비동기 이벤트·응답의 코드 근거를 틀리게 바꾸면 점선 + 근거 없음 표시가 되며, 화살촉과 동기·비동기·응답 표시는 각각 유지된다. 근거를 복구하면 같은 통신 표기의 실선으로 돌아온다
- [ ] 처음부터 추론 표시를 붙인 점선은 유효한 코드 근거 검사 뒤에도 점선 + 추론 표시로 남아, 서버가 강등한 점선 + 근거 없음 표시와 구분된다

- [ ] 존재하는 파일·줄이 그림의 의존성과 무관한 내용이어도 서버는 의미 오류를 판정하거나 그 이유로 강등하지 않는다. 파일·줄 존재 확인과 에이전트의 의미 판단을 구분한다.

### 미결 결정 (구현 전에 정한다)

1. **태그를 바꿀 때의 전이 (P1, 판단 필요)**
   - 서버가 강등한 요소의 태그를 `code`에서 `design`/`log`로 바꾸거나 `evidence`를 지운다. 이때 실선 복구, "서버 강등" 표시, 근거 없음 텍스트를 어떻게 할지 정해지지 않았다.
   - 지금 문서의 복구 조건은 "근거가 맞아지면"(위 12행 근처 규칙) 하나다. ADR-0005에도 이 전이가 없다.
2. **추론 점선에 틀린 `code` 근거가 붙은 경우 (P1, 판단 필요)**
   - 정해야 할 것: 근거 없음 텍스트를 붙일지, "서버 강등" 표시를 남길지.
   - 위험: "서버 강등" 표시를 남기면 나중에 근거를 고칠 때 원래 추론 점선이 실선으로 올라간다. 체크박스 "처음부터 점선으로 그린 화살표 … 실선으로 올리지 않는다"와 충돌한다.
3. **"`evidence`가 바뀌었는지"를 비교할 이전 상태 (P1 중 남은 빈틈, 판단 필요)**
   - `src/server.ts`의 `/api/elements/sync` 핸들러는 새 요소를 쓰기 전에 `elements.clear()`를 부른다. 그래서 수명주기 1의 "바뀌면 검사"를 비교할 이전 값이 없다.
   - 선택지: 이전 `evidence`를 따로 들고 있는다 / sync 때는 `code` 태그 요소를 전부 다시 검사한다.
4. **`evidence` 모양 검증 (P2, 판단 필요)**
   - 정해야 할 것: `code` 태그의 `path`·`line` 필수 여부, 줄 번호 기준(1부터인지).
   - 정해야 할 것: 필드 누락, 타입 오류, 파일 읽기 실패를 거부할지 강등할지. 지금 문서의 실패 조건은 "파일 없음"과 "줄이 범위 밖" 둘뿐이다. spec 7-3에도 모양만 있다.

### 문구·항목만 고칠 것 (판단 불필요)

- "그릴 때마다"(제목·What to build): 검사 **시점**(저장할 때가 아니라 그릴 때)을 뜻한다. 다시 검사하는 **조건**은 수명주기 1("`evidence` 칸이 바뀌면")이다. 이 구분이 드러나게 문구를 다듬는다. 근거: ADR-0005의 기각 항목 "저장(도면 승격) 시점에만 검사".

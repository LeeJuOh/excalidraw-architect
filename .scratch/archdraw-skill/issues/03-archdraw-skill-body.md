# 03: `archdraw` 판단 스킬 본문 — 라우팅 표, 줌 레벨, 캔버스 우선

> 확정된 라우팅 21행(review.md "행 확정 기록" → PRD 반영본)을 그대로 구현한다. 02 도그푸딩은 구현 뒤에 돌리며, 그 판정(`dogfooding-00.md`)이 이 이슈의 수정 사항으로 돌아온다.

**What to build:** 사용자가 `/archdraw 이 API 부르면 뭐가 일어나?`라고 하면 시퀀스 그림이 나오고, `/archdraw 구조가 어떻게 돼?`라고 하면 줌 레벨 그림이 나온다. 에이전트는 매 턴 행동 전에 캔버스를 보고, 사용자가 옮긴 배치는 정답으로 받고, 새 그림은 캔버스를 지우지 않고 옆에 그린다. 업스트림 `excalidraw-skill`은 삭제되고 조작법은 `archdraw`의 references로 옮겨진다.

- 스킬 본문 500줄 이하, 영어. Claude·Codex 공통 본문 하나를 유지하며, 01의 호스트별 호출 정책 파일과 사용 안내를 유지한다(스펙 "수동 스킬", 검수 R11). 상세는 references 3단계(조작법 / 라우팅 표 / 줌 레벨).
- 라우팅 표: 스펙 §1의 21행을 그대로. 행마다 **답하는 질문 한 문장** + 그림 종류 + 필수요소 + 라우팅 예외 + 그리는 규칙. 에이전트는 사용자 발화를 질문 중 하나로 읽고, 사용자가 부른 그림 이름보다 질문을 우선한다. 고른 이유는 채팅에 한 줄, 그림 제목(frame 이름)은 답하는 질문. 두 갈래로 읽힐 때만 되묻고, 되물을 땐 후보마다 아스키 미리보기. 개념 용어(Event Notification 등)는 원어 유지. API 계약 행은 표준 표기가 없는 근사형이라 스킬 문서에도 그렇게 적는다.
- 대화 중 사용(스펙 "대화 중 사용"·"변경안 표기", 2026-09-19 프레임 정리): 세 진입은 같은 동작이고 대상만 다르다. 정방향(에이전트 설명 → 그림, show-me류 요청과 같되 출력은 캔버스)·목적 질문(결정하려고 지금 상태 → §1 상황 그림)·역방향(`네가 이해한 대로 그려봐` = 구현 위임 전 이해 대조 → 코드에서 읽은 지금 구조 + 사람 말의 바꿀 것을 한 그림에, 변경안 표기 → 사용자 편집은 교정·제안·결정 중 하나다. 뜻이 분명하면 그대로 따르고, 분명하지 않으면 묻는다. 코드에 없는 내용은 사실로 받지 않는다. 언제 묻고 어떻게 표시할지는 절차로 적지 않고 모델에 맡긴다 — 2차 검수 A2). 한 번 부른 뒤 같은 대화에서 연결·순서가 들어간 답은 재호출 없이 그림 먼저. 이 동작을 공통 본문에 적고, 실제 후속 턴 적용과 압축 후 재호출·재개는 02 도그푸딩에서 확인한다(호스트의 영구 유지 보장으로 설명하지 않음). 변경안은 지금 구조 위에 바뀌는 부분만 새 색, 코드에 없는 선은 `설계` 태그 실선. "텍스트로 답해" 끄기 규칙은 적지 않는다(02에서 확인). 경계: 구조·흐름·경계는 캔버스, 코드·쿼리·값·이유는 텍스트. L5 아래는 그리지 않는다.
- 고정 포함 트리가 아닌 줌 레벨 5개 안내와 레벨별 허용 디테일 ([ADR-0004](../../../docs/adr/0004-five-zoom-levels.md)). 사용자에겐 번호 대신 이름("모듈 경계 그림")으로 말한다. 근거 추출은 원칙 3줄(선언 파일 → 디렉터리 관례 → import 추론은 점선), 스택 표 없음. 선언 파일은 "의존한다"의 근거이며, "부른다·구독한다"는 호출·구독 코드 줄이 있어야 실선(2차 검수 A3).
- 내부 탐색·저장 발화(검수 R07 일부): PRD §3의 내부 탐색과 §3.5 저장 범위·파일 단위를 따른다. 기존 내부 그림으로 화면을 이동·확대하거나 없으면 그린다. 저장 범위는 기본 전체, 명시한 경우 지정 그림이며 대상이 애매할 때만 묻는다.
- 산출물 경로·이름(2026-09-16): 저장 경로를 고정하지 않는다. 사용자가 지정한 경로·파일명은 그대로 따른다. 경로가 없으면 프로젝트의 기존 문서 배치를 보고 저장 폴더를 선택하고, 파일명이 없으면 그림 내용을 보고 영어 파일명을 정한다. 별도 경로·이름 확인 없이 저장하고, 성공 후 파일명을 포함한 전체 경로를 알려준다. 같은 경로에 파일이 있으면 자동 덮어쓰지 않고 06의 동명 파일 거부 결과를 알린다.
- 스냅샷은 06에서 디스크에 보관하며 TTL이 없다. 생성 성공 후 서버 종료·재시작 뒤에도 남고 자동 만료되지 않는다고 안내한다. 업스트림 메모리 방식의 유실 안내는 제품 규칙에 넣지 않는다.
- 스냅샷 이름을 생략하면 캔버스 내용을 나타내는 영어 이름(확장자 제외)을 정하고, 생성 시각을 UTC 초 단위로 앞에 붙여 `YYYY-MM-DD_HHmmssZ_<영어 이름>`으로 만든다(예: `2026-09-16_053012Z_order-flow`). 직접 지정한 이름은 그대로 사용한다. 생성 결과에 실제 이름과 전체 경로를 알린다. 같은 초·이름이 겹치면 06의 동명 거부 결과를 알린다.
- 미확인 필수요소가 있어도 "확인 못 함" 표시와 점선을 유지해 바로 저장하고, 미확인 항목을 사용자에게 알린다. 값 보완이나 추가 확인을 저장 전제조건으로 삼지 않는다.
- 그림 참조를 생성하고 탐색할 때 05의 frame으로 대상 그림을 구분한다. 06이 저장·재로드한 참조를 읽어 기존 내부 그림으로 이동·확대하며, 함께 불러온 공용 내부 그림을 중복 생성하지 않는다.
- 관통 규칙: 한 그림에 한 종류 / 진짜 이름 / 기본은 안 남김. 승격은 사용자 발화로만.
- **저장 상태 표시 (PRD §3.5, 2026-09-19):** 그림으로 답한 턴 끝에 `screenshot` 결과에 동봉된 그림별 저장 상태(저장 경로 / 저장 후 수정됨 / 파일 없음 / 미저장, 마지막 스냅샷)를 채팅 한 줄로 옮겨 적는다. 세거나 기억하지 않는다 — 값은 06 서버가 준다. 저장할지는 묻지 않는다. 사용자가 세션을 끝내자고 하면 미저장·저장 후 수정된 그림이 있을 때 1회만 저장할지 묻고 `session end`를 부른다. 그림마다·호출마다 묻는 지시는 넣지 않는다.
- 캔버스 우선: 턴 시작 `screenshot`, 사용자 표시는 교정·제안·결정 중 하나로 읽고 뜻이 분명하지 않으면 묻는다(삭제·의문 표시를 규칙으로 못 박지 않음), 자가 수정은 두 번 실패하면 멈추고 사용자에게 말함, 라벨 삭제는 수리 아님, 그림 밑 "안 그림" 줄.
- 과밀: 주노드 10~15 넘으면 개요 그림 + 묶음별 그림.
- 조작법·치수·색 규격은 업스트림 디자인 가이드를 `references/canvas-ops.md`로 옮긴다. 스킬 본문이 중복 정의하지 않는다. `install-skill` 커맨드는 삭제한다(플러그인 `skills/` 자동 로드).
- 선 표기(검수 R05): PRD §3 "선 표기"를 스킬과 조작 가이드에 적용한다. 추론 점선에는 `추론` 라벨, 각 그림에는 사용한 표기의 범례를 넣는다. `src/core/design-guide.ts`의 Arrow Binding Best Practices·의미별 선 규칙과 옮겨온 `references/canvas-ops.md`에서 dashed = async/optional/event 규칙을 교체한다. 응답 실선은 의도적인 UML 표기 차이로 적는다. 서버 강등·복구의 통신 표기 보존은 07 담당.
- 출처 규칙: yctimlin(MIT) 조작법은 이동하되 선 표기는 PRD에 맞게 교체, excalidraw-diagram-skill(라이선스 없음)은 원칙만 재작성, archify(MIT) 규칙은 재작성.

- [ ] 바운디드 컨텍스트가 박스 하나와 일치하는 경우, 모놀리스 내부에 여러 개인 경우, API·워커 여러 박스에 걸친 경우를 각각 실제 코드·설계에 맞게 표시한다

- [ ] "order-service 내부 보여줘"에 해당 그림이 있으면 화면을 그 그림으로 이동·확대하고 중복 생성하지 않는다. 없으면 기존 그림 옆에 새로 그린다
- [ ] 전체 구조·주문 내부·로그인 흐름이 있는 캔버스에서 "저장해"는 전체를 파일 하나로 export하고, "주문 내부 그림만 저장해"는 해당 그림만 export한다. 명확한 저장 범위는 다시 묻지 않는다
- [ ] 경로·파일명을 모두 지정하면 둘 다 그대로 사용한다. 사용자 지정 파일명을 영어로 바꾸지 않는다
- [ ] 경로만 지정하면 내용을 보고 영어 파일명을 정하고, 파일명만 지정하면 프로젝트의 기존 문서 배치를 보고 폴더를 선택한다
- [ ] 경로·파일명 없이 "저장해"라고 하면 에이전트가 프로젝트의 기존 문서 배치를 보고 폴더와 영어 파일명을 정해 확인 질문 없이 저장하고, 성공 후 전체 경로를 알려준다. 특정 산출물 폴더를 강제하지 않는다
- [ ] 대상 파일이 이미 있으면 자동 덮어쓰기나 자동 접미사로 우회하지 않고 충돌을 알린다. 저장 실패를 성공으로 안내하지 않는다
- [ ] 스냅샷 생성 성공 후 디스크에 보관되어 서버 종료·재시작 뒤에도 남고 자동 만료되지 않는다고 안내한다
- [ ] 이름 없는 스냅샷은 생성 시각의 UTC 초 단위와 캔버스 내용의 영어 이름으로 `YYYY-MM-DD_HHmmssZ_<영어 이름>`을 만들고, 직접 지정한 이름은 그대로 사용하며, 성공 결과에 실제 이름과 전체 경로를 알린다. 같은 초·이름의 충돌은 성공으로 안내하지 않는다
- [ ] 상위 그림 A와 내부 그림 B를 연결해 저장하고 새 캔버스 세션에서 불러온 뒤 "A 내부 보여줘"라고 하면 기존 B로 화면을 이동·확대하며 B를 다시 그리지 않는다(06과 통합 확인)
- [ ] A만 저장한 파일을 새 캔버스에서 불러온 뒤 "A 내부 보여줘"라고 하면, 저장에 포함되지 않은 그림임을 알리고 새로 그리거나 묻는다. 이름이 같은 다른 그림을 대신 보여주지 않는다(2차 검수 A5, 06과 통합 확인)
- [ ] "확인 못 함" 필수요소가 있는 그림에 "저장해"라고 하면 보완 질문 없이 저장하고, 성공한 경로와 미확인 항목을 알린다. 저장된 그림에도 점선과 "확인 못 함" 표시가 남는다
- [ ] 그림 A를 그리고 → A 저장 → 사용자가 브라우저에서 A 박스를 옮김 → 그림 B를 그린 뒤, 각 턴 끝 채팅 줄이 순서대로 "A 미저장" / "A 저장 경로" / "A 저장 후 수정됨 · B 미저장"을 보인다. 값은 `screenshot` 결과와 일치하고 대화 기록에서 센 것이 아니다(06과 통합 확인)
- [ ] 그림을 그린 뒤 "저장할까?"·"남길까?"를 묻지 않는다. 사용자가 "세션 끝내자"라고 했을 때 미저장 그림이 있으면 1회 묻고, 없으면 묻지 않고 `session end`한다


## 검증 방법과 결과 기록 (R10)

구현 담당 에이전트가 아래 방식으로 위 인수 기준을 확인한다. 항목별 기대 결과는 각 체크박스를 따르며, 결과에는 발화·초기 조건·기대 결과·실제 결과·통과/실패/미시험·근거를 남긴다. 의미 평가와 화면 확인은 별도 결과로 적는다. 보기 좋은 그림도 내용이 틀리면 의미 평가 실패다.

| 인수 기준 범위 | 관측 수단과 판정 |
|---|---|
| 라우팅 예시·허용 디테일·선 표기·줌 단계·공용 모듈·바운디드 컨텍스트 | 입력 코드·설계에서 기대 관계와 필수요소를 먼저 정한다. `describe`와 실제 요소 데이터의 라벨·연결·태그·선 스타일을 대조하고 스크린샷으로 표기와 범례를 확인한다. 그림 제목만으로 그림 종류를 판정하지 않는다. |
| 라우팅 표·본문 길이·shim·업스트림 스킬 및 커맨드 제거·디자인 가이드 | 문서·파일·커맨드 목록을 읽어 명시된 내용·줄 수·존재 여부와 대조한다. |
| 선택 이유·저장 범위·경로·파일명·충돌 및 미확인 항목 안내 | 대화 기록과 호출 인자·성공/실패 결과·실제 저장 파일을 함께 대조한다. 안내만으로 저장 성공을 판정하지 않는다. |
| 사용자 배치 유지·기존 그림 보존·옆에 새 그림 생성 | 전후 실제 요소 데이터에서 기존 ID·좌표·내용의 보존과 새 그림 위치를 비교한다. |
| 내부 탐색·공용 내부 그림 중복 방지·저장 후 재탐색 | 전후 요소 수·참조 대상을 비교하고, 이동 후 스크린샷으로 요청한 내부 그림이 화면에 보이는지 확인한다. 저장 후 재탐색은 06의 저장·재로드 구현 뒤 통합 확인한다. |
| 스냅샷 보관·이름·미확인 필수요소 저장 | 06의 파일·재시작 검증 결과와 대화 안내를 대조한다. 저장 후에도 점선·표시가 보이는지는 스크린샷으로 확인한다. |
| 저장 상태 한 줄·세션 종료 1회 질문 | 각 턴의 `screenshot` 결과 JSON과 채팅 줄을 대조한다. 그리는 중 저장 질문이 없고 종료 발화에만 질문이 있는지 대화 기록으로 확인한다. |
| 가독성·자가 수정 | 스크린샷에서 잘림·겹침·화살표 방해를 확인하고 수정 전후 이미지와 결과를 남긴다. 두 번 실패하면 중단·사용자 안내가 대화 기록에 있어야 한다. |

- [ ] 위 방식으로 인수 기준별 결과와 근거를 기록했다. 04~07 구현이 필요한 통합 확인은 해당 구현 뒤 수행하고, 그 전에는 미시험으로 남긴다. 03 본문 구현 착수를 막는 의존성으로 추가하지 않는다.
- [ ] 02 이후 with/without 비교 결과에 각 그림의 의미 평가(그림 종류·레벨·필수요소별 판정과 이유)와 스크린샷 확인(잘림·겹침 및 수정 결과)을 구분해 남겼다. 스킬을 쓴 결과가 더 낫다고 미리 결론짓지 않는다.

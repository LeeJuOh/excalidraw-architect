# 03: `archdraw` 판단 스킬 본문 — 라우팅 표, 줌 레벨, 캔버스 우선

> 확정된 라우팅 21행(review.md "행 확정 기록" → PRD 반영본)을 그대로 구현한다. 02 도그푸딩은 구현 뒤에 돌리며, 그 판정(`dogfooding-00.md`)이 이 이슈의 수정 사항으로 돌아온다.

**What to build:** 사용자가 `/archdraw 이 API 부르면 뭐가 일어나?`라고 하면 시퀀스 그림이 나오고, `/archdraw 구조가 어떻게 돼?`라고 하면 줌 레벨 그림이 나온다. 에이전트는 매 턴 행동 전에 캔버스를 보고, 사용자가 옮긴 배치는 정답으로 받고, 새 그림은 캔버스를 지우지 않고 옆에 그린다. 업스트림 `excalidraw-skill`은 삭제되고 조작법은 `archdraw`의 references로 옮겨진다.

- 스킬 본문 500줄 이하, 영어. 상세는 references 3단계(조작법 / 라우팅 표 / 줌 레벨).
- 라우팅 표: 스펙 §1의 21행을 그대로. 행마다 **답하는 질문 한 문장** + 그림 종류 + 필수요소 + 라우팅 예외 + 그리는 규칙. 에이전트는 사용자 발화를 질문 중 하나로 읽고, 사용자가 부른 그림 이름보다 질문을 우선한다. 고른 이유는 채팅에 한 줄, 그림 제목(frame 이름)은 답하는 질문. 두 갈래로 읽힐 때만 되묻고, 되물을 땐 후보마다 아스키 미리보기. 개념 용어(Event Notification 등)는 원어 유지. API 계약 행은 표준 표기가 없는 근사형이라 스킬 문서에도 그렇게 적는다.
- 대화 중 사용(스펙 "대화 중 사용"·"변경안 표기"): 정방향(에이전트 설명 → 그림)·역방향(`네가 이해한 대로 그려봐` → 사용자가 고친 그림이 정답). 한 번 부른 뒤 연결·순서가 들어간 답은 그림 먼저. 변경안은 지금 구조 위에 바뀌는 부분만 새 색, 코드에 없는 선은 `설계` 태그 실선. "텍스트로 답해" 끄기 규칙은 적지 않는다(02에서 확인).
- 줌 레벨 5개와 레벨별 허용 디테일 ([ADR-0004](../../../docs/adr/0004-five-zoom-levels.md)). 사용자에겐 번호 대신 이름("모듈 경계 그림")으로 말한다. 근거 추출은 원칙 3줄(선언 파일 → 디렉터리 관례 → import 추론은 점선), 스택 표 없음.
- 관통 규칙: 한 그림에 한 종류 / 진짜 이름 / 기본은 안 남김. 승격은 사용자 발화로만.
- 캔버스 우선: 턴 시작 `screenshot`, 사용자 표시는 고칠 곳, 자가 수정은 두 번 실패하면 멈추고 사용자에게 말함, 라벨 삭제는 수리 아님, 그림 밑 "안 그림" 줄.
- 과밀: 주노드 10~15 넘으면 개요 그림 + 묶음별 그림.
- 조작법·치수·색 규격은 업스트림 디자인 가이드를 `references/canvas-ops.md`로 옮긴다. 스킬 본문이 중복 정의하지 않는다. `install-skill` 커맨드는 삭제한다(플러그인 `skills/` 자동 로드).
- 출처 규칙: yctimlin(MIT) 조작법은 그대로, excalidraw-diagram-skill(라이선스 없음)은 원칙만 재작성, archify(MIT) 규칙은 재작성.

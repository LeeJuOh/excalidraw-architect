## 판정과 범위

**01의 설치 계약을 보완해 도그푸딩을 시작할 단계다. 03~07을 확정 설계로 일괄 구현하기에는 계약 누락과 설계 재검토 사항이 남아 있다.** 포크·CLI 중심 방향은 유지 가능하다.

검수 대상은 [PRD](spec.md), [이슈 01~07](issues/), [CONTEXT](../../CONTEXT.md), [ADR 0001~0005](../../docs/adr/)다. 현재 서버 코드, 참고 프로젝트 3종, 위키, 공식 문서를 대조했다. 설치·빌드·브라우저 실행 검증은 수행하지 않았다.

이 문서는 검수 결과와 후속 수정의 인계 기록이다. 아래 변경안은 아직 채택되지 않았으며, 제품 요구와 결정의 SSOT는 PRD·CONTEXT·ADR이다. 이번 기록 작업에서는 해당 결정·이슈 상태·구현 코드를 변경하지 않았다.

## 이어서 작업하는 순서

1. 현재 사용자 요청 범위와 기준 커밋 이후 변경을 확인하고, 아래에서 해당 이슈의 지적을 고른다. **완료 조건:** 대상 지적 ID와 이미 해결된 항목이 구분된다.
2. 해당 항목의 근거를 현재 파일에서 재확인한다. 호스트 지원 여부를 바꾸는 작업이면 연결된 공식 문서도 다시 확인한다. **완료 조건:** 확인된 사실과 설계 제안을 구분하고, 반영·기각·보류 중 처리 방향과 이유가 정해진다.
3. 허용된 수정 범위에서 PRD의 요구, 관련 ADR의 결정, 이슈의 작업·의존성·인수 기준을 맞춘다. 용어가 바뀌면 CONTEXT에도 반영한다. **완료 조건:** 관련 문서가 같은 동작을 요구하고, 검증 책임이 특정 이슈에 배정된다.
4. 각 지적의 **문서 완료 조건**을 확인하고 아래 처리 기록을 갱신한다. 구현까지 수행했다면 실행한 검증과 결과도 연결한다. **완료 조건:** 문서 반영 여부와 실행 검증 여부를 각각 보고할 수 있다.

### R01 — 설치된 소스에서 실행 파일까지의 경로가 빠졌다

- **근거:** [PRD](spec.md) Implementation Decisions의 shim·§7-5a, [01](issues/01-plugin-skeleton.md). shim은 `dist/bin.js`를 실행하지만 [.gitignore](../../.gitignore)는 `dist/`를 제외하며, [package.json](../../package.json)의 빌드는 별도 명령이다. [Claude 공식 문서](https://code.claude.com/docs/en/plugins-reference#nodejs-package-dependencies)는 캐시 설치 시 `npm ci --ignore-scripts`를 설명한다. 의존성 설치와 서버·프론트 빌드는 별개의 단계다.
- **영향:** 소스 레포 설치와 매니페스트 생성만 완료해도 shim의 실행 대상이 없을 수 있다. 개발자가 미리 빌드한 폴더에서는 이 결함이 가려진다.
- **수정 방향:** 빌드 결과를 포함한 배포 또는 최초 실행 준비 중 하나를 정하고, 두 호스트의 실행 위치·의존성·빌드 실패 처리를 01에 포함한다. npm 배포는 여러 선택지 중 하나다.
- **문서 완료 조건:** 깨끗한 설치에서 서버와 프론트 자산이 준비되는 경로가 명시되고, 두 호스트에서 설치→호출→캔버스의 박스 확인까지 검증하는 인수 기준이 있다.

### R02 — 캔버스 전체 복원을 그림 하나의 저장·복사로 사용할 수 없다

- **근거:** [PRD](spec.md) §3.5·스토리 17, [06](issues/06-snapshot-and-export-persistence.md). [buildSceneFile](../../src/core/scene-io.ts)는 전체 캔버스를 export하고, [snapshot restore](../../src/cli/commands/snapshot.ts)는 `clearCanvas()` 후 복원한다. `importScene`의 merge는 ID를 보존하며, [서버 batch 생성](../../src/server.ts)은 같은 ID를 `elements.set`으로 덮는다.
- **영향:** A·B 중 A만 도면으로 저장해도 B가 함께 저장된다. 과거 A를 전체 복원하면 현재 B가 사라지고, 같은 A를 merge로 불러오면 독립된 before/after 복사가 되지 않는다.
- **수정 방향:** 그림 선택 export, 복사 시 요소·frame·바인딩 ID 재매핑, 캔버스 전체 복원과 그림 추가를 구분한다. 파일명 계약은 R07에서 다룬다.
- **문서 완료 조건:** A·B 중 A만 저장, A 복사 후 B 유지, 복사본 수정 후 원본 유지, 전체 복원의 적용 범위를 05/06의 예시와 인수 기준으로 설명할 수 있다.

### R03 — 서버 분리와 공용 디스크 저장소의 범위를 맞춰야 한다

- **근거:** [04](issues/04-session-per-canvas.md)는 캔버스 서버를 분리하지만 [06](issues/06-snapshot-and-export-persistence.md)은 공용 데이터 폴더의 `snapshots/<name>.excalidraw`를 사용한다. [ADR-0005](../../docs/adr/0005-server-checks-evidence-and-demotes.md)는 서버 cwd를 레포 루트로 본다.
- **영향:** 서로 다른 캔버스 세션이나 프로젝트에서 `before`를 저장하면 같은 파일명이 충돌한다. 스킬 루트로 `cd`해서 shim을 호출하면 서버 cwd도 플러그인 쪽이 되어 근거·저장 경로가 대상 프로젝트와 어긋날 수 있다.
- **수정 방향:** 프로젝트 루트의 고정 방법, 프로젝트 간 격리, 같은 프로젝트 안 스냅샷 공유 범위, 동명 저장 정책을 정한다. 새 캔버스 세션에서 전날 스냅샷을 찾는 요구도 함께 충족시킨다.
- **문서 완료 조건:** 두 프로젝트·같은 프로젝트의 두 캔버스 세션·다음 날 새 캔버스 세션의 저장 및 복귀 결과가 각각 정의되고, 호출 cwd가 달라도 대상 프로젝트가 유지되는 인수 기준이 있다.

### R04 — 생성 후 수정과 자동 경고의 수명주기가 빠졌다

- **근거:** [07](issues/07-evidence-check.md)과 [ADR-0005](../../docs/adr/0005-server-checks-evidence-and-demotes.md)는 매번 검사를 요구하면서 생성 경로만 지정한다. [CLI apply](../../src/cli/commands/elements.ts)에는 update가 있고 [서버 PUT](../../src/server.ts)은 별도 저장 경로다.
- **영향:** 유효한 근거로 생성한 뒤 없는 파일·줄로 수정하는 경우가 지정된 검사 범위를 벗어난다. 원본 선의 수정·삭제 뒤 자동 생성한 “근거 없음” 텍스트를 갱신하거나 제거하는 규칙도 없다.
- **수정 방향:** 생성·수정·import·restore에서의 재검사 조건과 경고의 원본 요소 연결을 정의한다. 브라우저 편집·저장·재로드의 근거 태그 보존도 검증에 포함한다. 실제 왕복 유실은 이번 검수에서 재현하지 않았다.
- **문서 완료 조건:** 잘못된 근거로 수정→강등, 근거 보완→경고 처리, 선 삭제→경고 정리, 저장·재로드→태그 보존의 기대 결과가 07에 있다. “내리기만 한다”는 현재 ADR과 재검사 후 상태가 일치한다.

### R05 — 점선이 통신 방식과 불확실성을 동시에 뜻한다

- **근거:** [CONTEXT의 점선](../../CONTEXT.md)은 확인되지 않은 선·값을 뜻한다. [PRD](spec.md) §7-4·yctimlin과의 경계는 조작법을 옮겨오는데, [디자인 가이드](../../src/core/design-guide.ts)의 Arrow Binding Best Practices는 dashed를 비동기·이벤트에 사용한다.
- **영향:** 확인된 비동기 이벤트와 추측한 동기 호출의 표시가 겹친다. 변경하는 문장은 짧아도 그림이 전달하는 의미가 바뀌므로 표기 설계 문제다.
- **수정 방향:** 통신 방식과 근거 상태를 독립적으로 읽을 수 있게 표기·범례를 정하고, 가져오는 조작 가이드에도 반영한다.
- **문서 완료 조건:** 확인된 동기 호출·확인된 비동기 이벤트·추론 관계·근거 없음의 네 예시가 혼동 없이 구분된다.

### R06 — 모든 프로젝트가 같은 줌 포함 트리라는 가정은 재검토가 필요하다

- **근거:** [ADR-0004](../../docs/adr/0004-five-zoom-levels.md), [CONTEXT](../../CONTEXT.md)의 줌 레벨, [PRD](spec.md) §3의 DDD 매핑. [C4 공식 정의](https://c4model.com/abstractions/component)는 기능 경계와 JAR·패키지 구조를 별개의 축으로 설명한다.
- **설계 리스크:** Gradle의 `domain`·`adapter`가 각각 모듈이면 모듈 자체가 레이어다. 공용 모듈은 여러 배포 단위에서 사용될 수 있다. 바운디드 컨텍스트와 배포·빌드 모듈도 항상 일대일은 아니다. 이는 검수자의 반례이며, 실제 대상 프로젝트에서의 실패를 재현한 결과는 아니다.
- **수정 방향:** ADR-0004를 재검토해 단계 생략·공유 모듈 참조·DDD 경계 표시를 정한다. 5레벨을 안내 체계로 유지하면서 예외를 표현하는 방안도 가능하다.
- **문서 완료 조건:** 기능별 모듈, 레이어별 모듈, 여러 배포 단위가 쓰는 공용 모듈의 세 예시에서 어떤 그림으로 내려가는지 설명된다. 변경한 결정은 PRD·CONTEXT·ADR·03에 일관되게 반영된다.

### R07 — 줌 탐색·파일명·승격 조건의 책임이 이슈 사이에서 빠졌다

- **근거:** [PRD](spec.md) 스토리 10·15, §3의 하위 그림 참조, §3.5의 필수요소 규칙. [06](issues/06-snapshot-and-export-persistence.md)은 파일명을 [03](issues/03-archdraw-skill-body.md)이 정한다고 위임하지만 03의 작업·인수 기준에는 해당 계약이 없다.
- **영향:** 현재 체크박스를 모두 완료해도 부모 박스에서 하위 그림 열기, 다음 에이전트 세션에서 이어가기, “확인 못 함”이 남은 도면의 저장 처리가 빠질 수 있다.
- **수정 방향:** 실제 파일명 예시, 부모 박스↔자식 frame/파일 참조, 재로드 후 탐색, 미확인 필수요소의 저장 전 확인을 담당 이슈에 배정한다. 저장을 차단할지 고지 후 허용할지도 정의한다.
- **문서 완료 조건:** 그림 두 개를 연결해 저장→새 캔버스 세션에서 열기→하위 그림 탐색의 예시와, 미확인 필수요소가 있는 그림을 저장할 때의 기대 결과가 있다.

### R08 — 명시한 착수 조건과 Blocked by가 다르다

- **근거:** [05](issues/05-frame-element.md)는 [02](issues/02-dogfooding-round-zero.md)의 frame 검증을 착수 조건으로 적었지만 `Blocked by`는 01뿐이다. [03](issues/03-archdraw-skill-body.md)은 새 그림을 frame으로 만드는 PRD를 따라야 하지만 05 의존성이 없다.
- **영향:** 티켓 순서대로 실행하는 에이전트가 검증 전 구현을 시작하거나, 아직 없는 frame 기능을 전제로 스킬을 완료할 수 있다. 선행 이슈가 있다는 이유만으로 `ready-for-agent` 자체가 잘못된 것은 아니다.
- **수정 방향:** 기술 검증과 정식 frame 구현의 순서를 구분하고, 본문·의존성·통합 인수 기준을 맞춘다. 04/06/07의 “도그푸딩 후 조정”이 착수 조건인지 참고 사항인지도 R09의 결정에 맞춘다.
- **문서 완료 조건:** 모든 이슈의 명시적 착수 조건이 의존성에 반영되고, 지원되지 않은 커맨드·요소를 최종 스킬의 완료 조건으로 먼저 요구하는 순서가 해소된다.

### R09 — 확정 요구와 실험으로 추릴 규칙을 구분해야 한다

- **근거:** [PRD](spec.md) Further Notes는 “모드만 미검증”과 “세 번 이상 교정된 규칙만 남김”을 함께 적는다. [03](issues/03-archdraw-skill-body.md)은 후자를 따르면서 상황 17개·줌 레벨 5개를 고정 요구한다. PRD는 상황을 열거하지만 모든 상황의 질문·그림 종류·필수요소 표를 완성하지는 않았다.
- **영향:** 교정되지 않은 줌 규칙을 유지할지 제거할지, 나머지 라우팅의 필수요소를 누가 결정할지 구현자가 추측하게 된다.
- **수정 방향:** 합의된 제품 요구, 도그푸딩으로 추릴 행동 규칙, 아직 설계할 라우팅 행을 구분한다. 첫 검증 범위를 정하거나 17개 전체 표를 확정하는 방식 중 작업 범위에 맞게 선택한다.
- **문서 완료 조건:** 각 검증 대상이 유지·수정·제거되는 조건이 명확하고, 03이 구현할 라우팅 행의 필수요소가 정의되거나 그 정의 작업이 명시적으로 배정된다.

### R10 — describe 출력만으로 무엇을 판정하는지 좁혀야 한다

- **근거:** [PRD](spec.md) Testing Decisions는 `describe`로 그림 종류·금지 디테일·좌표를 판정해 육안 검사 없이 자동화한다고 한다. [describeScene](../../src/core/describe.ts)은 요소·라벨·반올림한 좌표 등의 요약이며, 의미적 정답을 판정하는 채점 규칙은 별도로 필요하다.
- **영향:** 라벨과 좌표가 있는 그림을 생성했다는 사실만으로 올바른 시퀀스·사용자 표시 해석·시각 품질까지 통과로 볼 수 있다. 자동화 불가능이라는 지적이 아니라, 판정 기준과 관측 수단이 빠졌다는 지적이다.
- **수정 방향:** 요소·좌표·저장 결과의 결정론적 검사와 그림의 의미·사용자 피드백·시각 품질 평가를 나눈다. [archify의 Delivery](../../references/archify/archify/SKILL.md)도 구조 검증·브라우저 동작·시각 평가를 구분한다. [위키 검증 레이어](../../wiki/concepts/verification-layers.md)는 이 구분의 보조 참고다.
- **문서 완료 조건:** 각 인수 기준에 관측 수단과 판정 기준이 있고, with/without 비교의 의미 평가 및 브라우저 확인이 별도 결과로 기록된다.

### R11 — Codex 수동 호출 전용 정책을 별도로 명세해야 한다

- **근거:** [PRD](spec.md)의 수동 스킬 설정과 [01](issues/01-plugin-skeleton.md)은 `disable-model-invocation: true`를 공통으로 적는다. 검수 당시 [Codex 공식 문서](https://learn.chatgpt.com/docs/build-skills#optional-metadata)는 `agents/openai.yaml`의 `policy.allow_implicit_invocation: false`와 명시적 `$skill` 호출을 안내한다.
- **영향:** Claude용 frontmatter를 적었다는 사실만으로 Codex에서도 수동 전용이라는 보장이 성립하지 않는다. 두 호스트의 사용자 호출 표기도 구분할 필요가 있다.
- **수정 방향:** 공통 본문과 호스트별 호출 정책·사용 예시를 구분하고 설치 검증에 포함한다. 루트 `plugin.json`·`mcp.json`은 [공식 portable 형식](https://developers.openai.com/plugins/build/plugins)과 맞으므로 경로 오류로 수정할 대상이 아니다.
- **문서 완료 조건:** Claude·Codex에서 명시적 호출이 동작하고 일반 발화로 자동 호출되지 않는지 확인하는 인수 기준이 있으며, 후속 턴에서 규칙을 이어가는 동작도 확인 범위에 포함된다.

## 표현·과거 기록 정리

이 항목들은 현재 결정의 의미를 유지하면서 정리할 수 있다.

- **E01:** [PRD](spec.md) 첫머리의 “이슈 미작성”과 Further Notes·Handoff의 포크 생성·문서 이동 지시가 현재 상태와 다르다. **문서 완료 조건:** 현재 이슈로 연결되며, 이미 끝난 레포 생성·이관을 다음 행동으로 안내하지 않는다.
- **E02:** PRD에 폐기된 “스택별 어댑터 테이블”과 `장`·`C4 레벨`·`영향범위` 등 구용어가 남아 있다. **문서 완료 조건:** 현재 결정을 설명하는 문장은 [CONTEXT](../../CONTEXT.md)와 일치하고, 변경 이력이 필요한 경우에만 과거 표현으로 구분한다. 레벨의 의미 자체를 바꾸는 작업은 R06으로 다룬다.

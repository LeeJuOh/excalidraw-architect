## Decisions Made

| 정한 것 | 값 | 이유 |
|---|---|---|
| 변경 상태 라벨 | `[added]` `[removed]` `[modified]` | 문서에 값이 없어서 에이전트가 정했다. GitHub REST API의 파일 상태와 같은 말이고, `[sync]`와 같은 괄호 모양이다. 사용자: "문제없어 보이긴 하네" |
| 계약 메모지 글꼴 | 가이드 문서에 "a monospace font"라고만 적었다 | 글꼴은 이슈 05가 정한다(spec, 이슈 03) |
| 저장 절에서 옮긴 것 | 경로·파일 이름·스냅샷뿐 아니라 범위와 미확인 값 문단도 옮겼다 | 이슈는 "저장 상태 한 줄 문단만 남긴다"고 했다. 에이전트의 해석이다 |
| 레이어 문장 | "Violations differ per module"을 지우지 않고 "Dependencies differ per module"로 바꿨다 | spec §3 L4: "의존이 모듈마다 달라서 레이어 그림이 모듈별로 가치 있음" |
| 가이드 문서에 더한 세부 4개 | 라벨은 이름 다음 줄에 둔다. 바뀐 줄마다 글자 요소를 따로 만든다. 메모지에는 라벨이 없다. `strokeColor: "transparent"` | 스펙 리뷰가 "요구에 없지만 무해"라고 했다 |

## What Didn't Work

- ⚠️ **사용자는 "정할 것이 있다"를 이해하지 못했다.** 첫 질문에 "먼 소리야, 03 구현 차례라매"라는 답을 들었다. 작은 값은 추천값으로 넣고, 끝 보고에 "임의로 정한 것"으로 적는다. 구현 도중에 묻지 않는다.
- ⚠️ **영역 색 문제를 6번에 걸쳐 설명했다.** 표, ADR 인용, 색 정책 설명은 모두 통하지 않았다("먼 소리지", "장황하게 말하지 마"). 사용자가 "우리 색 정책이 뭐야"라고 물은 뒤에도 질문이 무엇인지 잃었다. 통할 만한 모양은 First Action의 문장이다: 문제 한 줄 + "바뀐 것이 없는 영역이 노랑 → 수정됨으로 읽힘" + 질문 하나. ADR 번호나 문서 이름을 앞에 두지 않는다.

## What Worked

- 검사 스크립트를 먼저 고치고(새 구조는 실패) 문서를 채웠다. 목차 질문을 일부러 틀리게 바꿔 검사가 실패하는 것을 확인했다.
- `/code-review` 2축 병렬. 자동 검사가 통과하는데도 가이드 문서의 중복과 닿지 않는 규칙을 찾았다.

## What Worked

- **선택지를 캔버스에 견본으로 그렸다.** 글로 설명한 A/B/C는 통하지 않았다("뭔 소리야"). 사용자가 "캔버스 예시로 그려 봐"라고 했고, 견본을 본 뒤에 바로 골랐다. 표기를 정할 때는 견본을 먼저 그린다.
- **장면으로 설명했다.** "화살표 옆에 메모지가 있다 → 당신이 '쿠폰을 여러 개 받게 바꾸자'고 말한다 → 바뀌는 것은 한 줄이다". 추상적인 문장은 통하지 않았다.
- **이름의 근거를 출처 표로 붙였다**(출처 / 부르는 말). 기억에서 온 것은 "기억이다, unverified"라고 적었다.
- **고친 뒤에 "당신이 말하지 않았는데 제가 넣은 것"을 따로 보고했다.**
- 계속 유효(이전 세션): 결론 한 줄 → 작은 표 하나 → 질문 하나. 첫 보고에서 사용자의 목표와 문제를 에이전트의 말로 다시 말한다. 이슈 문서는 전체 경로로 부른다.

## What Didn't Work

- ⚠️ **긴 보고.** 첫 보고(목표 + 문제 + 상태 표 + 설명 1/9 + 질문)에 "장황하게 말하지 마"를 들었다. 통한 길이: 답 한 줄 + 표 하나(2~4줄) + 질문 하나.
- ⚠️ **사용자가 이미 말한 것을 다시 물었다.** "배경은 회색으로 하자"를 들은 뒤에 "전체가 새로 생기면 초록 배경"을 남겼고, 같은 것을 두 번 더 확인했다. 사용자: "항상 회색으로 가자고 말했잖아". 사용자가 정한 것은 예외를 만들지 말고 끝까지 적용한다. 같은 결정을 다시 묻지 않는다.
- ⚠️ **"구현을 시작합니까?"를 5번 물었다.** 사용자는 매번 다른 일(ADR, PRD, 핸드오프)을 지시했다. 다음 세션에서는 묻지 않고 구현한다.
- ⚠️ **에이전트의 작업 말로 보고했다.** "범위 표의 나머지", "이슈 문서의 옛 이름(1곳, 2곳)"을 사용자가 이해하지 못했다. 통한 말: "03 이슈를 구현하면 그것이 고쳐집니다. 둘은 같은 일입니다."
- ⚠️ **만든 이름을 추천했다.** 위 "Decisions Made" 참조. 이름을 정할 때는 조사 문서와 표준에서 먼저 찾는다.
- **캔버스 견본의 이름이 옛 견본과 겹쳤다**(둘 다 "A", "B"). 사용자: "필요 없는 거 다 지워, 헷갈려". 새 견본을 그리기 전에 끝난 견본을 지울지 묻는다.
- 계속 유효(이전 세션): 확인하지 않은 말을 사실처럼 말하지 않는다. 싼 선택을 먼저 추천하지 않는다(사용자는 "정석이 무엇이냐"를 묻는다). 번호만으로 부르지 않는다. 보고와 결정 요청을 섞지 않는다. 개수는 세고 말한다.

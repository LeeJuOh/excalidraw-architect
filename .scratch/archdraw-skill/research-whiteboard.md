## 1. 한 줄 요약

같은 문제를 반대 시점에서 푼다. Whiteboard는 구현 **뒤에** 사람이 diff를 이해하게 돕는다. archdraw는 구현 **전에** 사람과 에이전트가 이해를 맞추게 돕는다. README가 인용한 Geoffrey Litt "understanding is the new bottleneck"은 우리 PRD 문제 정의와 같다.

| | Whiteboard | archdraw |
|---|---|---|
| 시점 | 구현 뒤, 브랜치·diff 리뷰 | 구현 전, 위임 전 대조 |
| 사람 | 읽고 선택만 한다. 편집 불가 | 캔버스를 직접 고친다 |
| 그림 형태 | 구조화 JSON 블록. 레이아웃은 앱(ELK) **(에이전트)** | 자유 도형. 레이아웃은 에이전트 |
| 종류 선택 | 규칙 4줄 (`authoring.md:16-20`) | 상황 21행 + 줌 레벨 5단계 |
| 근거 | 커밋 고정 파일:줄. 틀리면 쓰기 거부 **(에이전트)** | 근거 태그·등급. 틀리면 점선 강등(ADR-0005) |
| 코드에 없는 것 | 개념 없음 | `설계` 태그 |
| 결정 기록 | 트레이스 원문 인용, 글자 대조 검증 **(에이전트)** | 범위 밖(2차 검수 C) |
| 피드백 | 선택 → "Copy for Agent" → 클립보드 → 붙여 넣기 **(에이전트)** | 사용자 표시를 스크린샷으로 읽음 |

## 2. 그림 종류 선택 규칙 비교

그쪽 규칙 (`authoring.md:16-20`):

- `sequence` — 참여자가 시간에 따라 상호작용
- `flow_diagram` — 분기, 재시도, 상태 전이
- `database_lens` — 스키마 변경, 누가 읽고 쓰는지
- `code_peek` — 변경이 대부분 계약이면 핵심 타입·인터페이스

**우리가 나은 점.** 필수요소, 라우팅 예외, 백엔드 전용 표기(장애 타임라인, 락 레인, 성능 워터폴, 배포 맵, 저장소 토폴로지). 그쪽 블록으로는 이 그림들을 그릴 수 없다.

**그쪽이 나은 점.** §3의 1~4.

## 4. 가져오지 않을 것

- **구조화 블록 전체.** 사람이 편집할 수 없게 된다. "같이 고친다"와 충돌한다.
- **트레이스 수집.** `~/.claude/settings.json`에 hook을 설치하고 원격(S3 또는 호스팅)에 올린다 **(에이전트)**. 결정 기록은 범위 밖이다.
- **쓰기 잠금(lease).** 쓰는 주체가 여럿일 때 필요하다. 우리는 "사용자가 옮긴 것이 정답" 규칙으로 충분하다.

# archdraw-report

archdraw 도그푸딩 기록을 사람 대신 채운다. 판단은 하지 않고 기록만 한다. 규칙을 유지할지 고칠지는 사용자가 모인 이슈를 보고 나중에 정한다.

1. **모은다.**
   - 발화: 이 대화에서 사용자가 archdraw에 시킨 말. 사용자가 쓴 언어 그대로 옮기고 번역하지 않는다.
   - 나온 그림: archdraw MCP 툴 `describe_scene`을 부른다. 툴이 없거나 호출이 실패하면 `(캔버스 없음)`이라고 쓰고 계속한다. 다른 방법으로 캔버스를 읽지 않는다.
   - 불만/고친 것, 원했던 것: 대화에서 사용자가 이미 한 말에서 찾는다.
2. **묻는다.** 불만/고친 것과 원했던 것 중 대화에 없는 것만 한 번에 묻는다. 둘 다 있으면 묻지 않는다. 캔버스가 없어도 원했던 것은 묻는다.
3. **이름을 뺀다.** 이 레포는 공개다. 제목과 본문에서 회사명·클래스명·테이블명을 일반 말(`회사`, `주문 서비스`, `주문 테이블`)로 바꾼다. 발화도 이름만 바꾸고 나머지는 그대로 둔다. 이름인지 확신이 없으면 올리기 전에 사용자에게 묻는다.
4. **쓴다.** 제목은 발화를 요약한 한 줄이다. 본문은 아래 네 칸을 이 순서로 항상 모두 쓴다. 발화 칸 말고는 한국어로 쓴다.
   ```
   ## 발화
   ## 나온 그림
   ## 불만/고친 것
   ## 원했던 것
   ```
5. **올린다.** `gh issue create --repo LeeJuOh/excalidraw-architect --label dogfooding --title "<제목>" --body-file -`에 본문을 표준 입력으로 넘긴다. 성공하면 이슈 URL을 알려준다.
6. **`gh`가 실패해도 끝내지 않는다.** `gh`가 없거나, 로그인이 안 됐거나, 이슈 생성이 실패하면 완성된 제목과 본문을 채팅에 내주고 사용자가 붙여넣게 한다. 네트워크 실패면 이슈가 이미 생겼을 수 있다. 이때는 "붙여넣기 전에 이 레포의 최근 `dogfooding` 이슈를 확인하라"를 한 줄 붙인다.

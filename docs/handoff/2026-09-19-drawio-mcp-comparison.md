# drawio-mcp 비교 → archdraw 반영 후보 4개 (1·2번 완료, 2번 Q3부터 재개)

## Goal

`references/drawio-mcp/`(jgraph 공식) 비교에서 골라낸 관행 4개를 하나씩 결정해 이슈에 반영한다. 1번(규격 SSOT)과 2번 좌표 규칙의 Q1·Q2는 결정·반영·커밋 완료. 남은 것은 2번 Q3(그림 종류별 열·행 의미), 4번(서버 normalize), 07 박스 강등 갭, 작은 것들.

## First Action

`/grill-with-docs`로 **2번 Q3**을 사용자에게 **하나만** 묻는다. 묻기 전 맥락 세 줄: 이슈 09에 적힌 공식 `x = 열×320+40`, `y = 행×180+40`은 (열, 행)을 받는데, 열·행이 뭘 뜻하는지는 그림 종류마다 다르다(시퀀스: 열=참여자·행=시간 / 박스-화살표: 행=층·열=형제 / 타임라인·워터폴: 열=시간). 안 적으면 에이전트가 시퀀스를 눕히거나 층을 옆으로 늘어놓는다.

> **Q3 열·행 의미를 적는 단위**: (a) 그림 종류 단위 (b) 상황 21행 각각 (c) 안 적음. 추천 (a). 놓이는 곳은 **이슈 03(스킬)** — 라우팅 표와 붙어야 하므로. 09 md는 공식만.

주의: 이전 핸드오프의 "그림 종류 5~6개"는 틀렸다. PRD §1 21행의 `그림:` 항목을 세면 박스-화살표(변형 여럿)·배포 중첩 사각형·ERD·오버레이·상태도·시퀀스(+신뢰 경계)·API 계약 근사형·파이프라인·DFD·스윔레인·타임라인·레인 타임라인·트레이스 워터폴 — **10개 안팎**. (a)로 가면 열·행 줄이 10줄쯤이고, 가로 시간축 계열(타임라인·워터폴·레인 타임라인)은 (열, 행) 격자가 아니라 "시간 → x 비례"라 공식 예외일 수 있다. Q3 답 받을 때 이 예외를 같이 확정한다.

## Context

세션 흐름: 큰그림 보고 → Q1 제시 → 사용자 "drawio처럼 하려면 서버 코드 바꿔야 하나?" → "drawio도 LLM에게 텍스트 지시, (a)=drawio 그대로" 설명 → Q1 (c) 확정 → 이슈 09·02 반영 → 사용자 "구체적으로 했나" → 구멍 4개 발견(원점·툴 유지·기존 그림 추가·숫자) → Q1-보강(기존 그림에 추가) (b) 확정 → Q2 박스 크기 (c) 200×60 확정 → 숫자 반영 → 커밋 `7c4325a` → Q3 제시한 상태에서 핸드오프.

사용자 특성(유지): 질문 한 번에 하나. 답이 길면 끊는다. "왜 문제냐"를 묻는 경우가 많으니 **장면 3단계로**(에이전트가 그림 → 사용자가 옮김 → 에이전트가 박스 추가) 보여주면 통했다. "우리 원래는 어떻게 했는데"·"drawio는 어떻게 하는데"를 자주 물으니 선택지 제시 전에 **현재 업스트림 값 vs drawio 값 표**를 먼저 두면 질문이 줄었다.

## Decisions Made

- **Q1 (c)** — 에이전트가 md 공식으로 직접 찍음, 서버 변경 없음, 도그푸딩 뒤 필요하면 서버 배치로 승격. drawio 자체가 (a) 방식(텍스트 지시, `shared/xml-reference.md` "Reasoning budget" 절)이라 (a)=drawio 그대로임을 사용자가 확인하고 확정.
- **Q1-보강 (b)** — 기존 그림에 요소 추가는 공식 안 쓰고 이웃 옆 간격만. drawio는 매번 XML 전체를 새로 열어 이 케이스가 없다(`get_page`/`set_page`도 페이지 통째 교체). 우리 PRD "옮긴 배치 = 정답"에서 파생된 우리 규칙.
- **Q2 (c)** — 200×60 고정. 가변(`max(160, 글자수×12)`, 업스트림 SKILL.md 값)은 열 최대 너비 계산이 생겨 Q1 Do NOT과 충돌해 기각. 140 고정(drawio)은 진짜 이름이 2~3줄로 꺾여 기각.
- **간격 320/180·여백 40** — 내가 정한 파생값(박스 + 라벨 화살표 최소 120px). 사용자 이의 없음. 도그푸딩 조정 대상.
- 이전 세션 유지: 1번 제3안(ADR-0006), MCP-only 지원, 조작법(스킬) vs 규격(서버 md) 구분, 09 분리, Do NOT은 좌표·배치에만.

## What Worked

- **"우리 원래는?" 표** — 업스트림 두 곳 값(`design-guide.ts` 120 / SKILL.md 160)과 drawio 값을 표로 먼저 놓으니 사용자가 "두 곳이 다르네 → 통합하자며"로 바로 1번 결정과 연결했다.
- **장면으로 갭 설명** — "기존 그림에 추가"가 왜 문제인지 추상적으로 말하니 "무슨 말이냐"였고, 3단계 장면으로 다시 쓰니 바로 확정.
- **"구체적으로 했나" 자문에 구멍 4개 표** — 원점·툴 유지·기존 그림·숫자. 두 개는 내가 채우고 하나만 물었다.

## What Didn't Work

- ⚠️ **Q1-보강을 맥락 없이 던졌다.** "(a)로 한다며 왜 또 묻냐"로 끊겼다. 보강 질문은 반드시 "이미 정한 것은 유지, 그 안의 경계 하나가 빈다"를 먼저.
- ⚠️ **Q2를 두 번 다시 설명했다.** 첫 제시가 Q1 반영 보고 뒤에 붙어 묻혔다. 질문은 보고와 분리해 단독 턴으로.
- "그림 종류 5~6개"를 세지 않고 말했다 — 실제는 10개 안팎. 숫자는 세고 말할 것.

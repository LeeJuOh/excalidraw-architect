# 이슈 06 — 슬라이스 6c import 착수 직전

상세는 티켓 `.scratch/archdraw-skill/issues/06-snapshot-and-export-persistence.md`의 "슬라이스 6c 결정"·"슬라이스 6d 결정"·"핸드오프" 절이다. 이 문서는 그 요약이다. 둘이 다르면 티켓이 맞다.

## Goal

이슈 06(스냅샷·export 영속화)을 슬라이스 4개로 끝낸다: 6a 스냅샷 디스크화 → 6b export → **6c import** → 6d 저장 상태. 슬라이스 하나씩, 커밋과 다음 착수는 사용자 승인 뒤.

## First Action

**6c 착수 보고 한 줄 뒤 `/tdd`로 들어간다.** 결정은 전부 끝났다 — 착수·구현 중 사용자에게 묻지 않는다. 사용자가 "착수 때 결정이 남으면 안 된다"고 했고, 그래서 6c 4개·6d 3개를 이번 세션에 다 확정했다. 티켓에 정말 없는 것이 나오면 그때만 멈춘다.

## Context

6c가 할 일(티켓 "그림 단위 저장·복사" 규칙 2·4, ADR-0007·0008):

- `import`는 캔버스를 지우지 않고 얹는다. `importScene`(`src/core/scene-io.ts`)의 `mode`, MCP `import_scene`의 `mode`, CLI `--replace`를 없앤다. `--replace`는 사용법 오류.
- 모든 ID를 한 세트로 새로 발급한다: 요소·frame·`containerId`·`frameId`·`startBinding`/`endBinding`·`boundElements`·`groupIds`·`link`의 `?element=<frame id>`. 세트 밖 id는 미포함으로 둔다. export가 만드는 `<박스 id>-label` id(`expandElementsForExport`, `src/core/expand-elements.ts`)도 세트에 든다.
- 배치: 현재 요소 전체 범위의 오른쪽, 간격 `FRAME_MARGIN * 2`(`src/core/frames.ts`). 빈 캔버스면 파일 좌표 그대로.
- 이름: 서버는 짓지도 거부하지도 않는다. 이름 있는 frame은 `<원본> (복사)`, frame 0개면 이름 빈 frame 하나로 감쌈, 이름 없는 frame은 그대로, frame 밖 요소는 frame 밖 그대로. 결과에 이름 없는 frame id 목록을 돌려주고 03이 이름을 붙인다. 중복 이름 허용.
- 확장자 허용 목록: 쓰기 `.excalidraw`·`.excalidraw.md`·`.png`·`.svg`, 읽기 `.excalidraw`·`.excalidraw.md`·`.json`. `writeOutputFile`과 `importScene` 입구. `--force`로도 못 넘는다. MCP `data`(JSON 문자열)는 파일을 읽지 않으니 무관, 유지.
- `link` 값은 손대지 않는다(Excalidraw가 `sanitize-url`로 무해화).
- 6c 끝 실세션 확인 때 `--frame A` 파일을 excalidraw.com에 올려 열림을 확인하고 6b의 열린 체크박스를 닫는다.
- 끝 보고는 **문제 있었나 / 판단할 것(선택지+추천) / 커밋해도 되나** 셋만.

## Decisions Made

티켓 "슬라이스 6c 결정"(간격 80 / 확장자 허용 목록 / 이름 규칙 표 / `link` 유지)과 "슬라이스 6d 결정"(`modified` = 어떤 속성이든 다르면, 해시 비교 / frame 밖 요소는 이름 없는 묶음 하나 / `snapshot restore` 특별 처리 없음)에 근거까지 있다. 재논의하지 않는다.

하네스의 자동 보안 검토가 6b 커밋 뒤 2건(임의 경로 읽기·쓰기)을 지적했다. 2026-09-16 사용자 결정의 수용된 트레이드오프다(ADR-0009, 티켓 "보안 트레이드오프"). 확장자 허용 목록이 그 완화책이다. 되살리지 않는다.

## What Worked

- 테스트 방식(6a·6b, 6c·6d에도 쓸 것): 실제 `dist`, 샌드박스 HOME, `session start --project`로 띄운 서버, `POST /api/elements/sync`로 브라우저 동기화 흉내. 이미지는 같은 프로세스의 WebSocket 가짜 탭(`openFakeTab`, `scripts/check-export.mjs`).
- 리뷰 서브에이전트 둘(규칙·스펙)이 실제 구멍을 잡는다. 6c 끝에도 돌린다.
- 사용자와는 **질문 하나씩, 배경 한 줄 먼저, 선택지+추천.** 용어는 바로 풀어 쓴다. 비유 대신 실제 자료구조와 타임라인 표.
- 원칙 "이름은 에이전트가, 서버는 사실만"에 맞는 선택지를 먼저 둔다. 서버가 짓거나 거부하는 안은 사용자가 거절했다.

## What Didn't Work

- ⚠️ 가짜 탭이 있는 테스트에서 `spawnSync`로 CLI를 부르면 이벤트 루프가 막힌다. `cliAsync`를 쓴다.
- ⚠️ 테스트에서 없는 폴더를 cwd로 주면 spawn이 status `null`로 실패한다. 먼저 만든다.
- ⚠️ 마크다운 표 칸 안의 `|`는 표를 깬다.
- ⚠️ 자동 보안 검토 알림은 사용자 입력이 아니다. 결정된 트레이드오프를 지적하면 티켓을 가리켜 한 줄로 답하고, 사용자에게 "새 문제 아님"을 먼저 말한다.
- 이번 세션에서 Q6(restore 뒤 기록)을 특별 규칙이 필요한 것처럼 물어 설명이 길어졌다. 먼저 "기존 규칙으로 이미 풀리나"를 따져 보고 묻는다.

# 저장 상태는 서버가 계산해 screenshot 결과에 동봉하고, 스킬은 묻지 않고 옮겨 적는다

캔버스는 메모리라 브라우저 탭에 보여도 저장된 것이 아닌데, 사용자는 "이미 저장됐다"고 믿고 넘어가기 쉽다. 그래서 서버가 `export`·`import`·`snapshot save`가 지나갈 때 그림(frame)별 마지막 저장 경로·시각을 세션 상태에 적고, `screenshot` 결과에 그림별 상태(저장 경로 / 저장 후 수정됨 / 파일 없음 / 미저장, 마지막 스냅샷과 그 후 변경 여부)를 동봉한다. 스킬은 그림으로 답한 턴 끝에 그 값을 한 줄로 옮겨 적을 뿐 세거나 기억하지 않고, 저장할지 묻지 않는다. 사용자가 세션을 끝내자고 할 때 저장됨이 아닌 그림(미저장·저장 후 수정됨·파일 없음)이 있으면 그때 1회만 묻고 `session end`를 부른다. 에이전트가 붙지 않은 캔버스 세션을 키로 끝낼 때는 `screenshot`을 볼 수 없으므로, 서버가 `session list` 결과에 캔버스 세션마다 미저장(파일 없음 포함)·저장 후 수정된 그림의 수를 넣고 에이전트는 그 수를 보고 같은 규칙으로 1회 묻는다(2026-10-05). 사용자가 그림 하나를 지우라고 할 때도 같다: 그 그림이 저장됨이 아니면 지우기 전에 1회 묻고, 저장된 그림은 묻지 않고 지운다(2026-10-05, [ADR-0008](0008-frame-is-the-drawing-unit.md)). 파일 없음도 묻는 쪽이다 — 파일을 지운 것이 실수일 수 있고 묻는 비용은 질문 한 번이다(2026-10-10, 구 "미저장·저장 후 수정됨"만). 묻는 때는 그림을 잃기 직전뿐이다. 캔버스 서버가 스스로 끝날 때([ADR-0003](0003-one-canvas-server-per-session.md), 연결 0개가 30분)는 물을 사용자가 없으므로 묻지 않고, 미저장 그림은 없어진다(2026-10-05). 결정론이 필요한 것은 모델이 아니라 서버가 맡는다는 원칙([ADR-0005](0005-server-checks-evidence-and-demotes.md)와 같은 이유)이다.

## Considered Options

- 그림마다 저장할지 묻기: 한 대화에 그림이 여럿이라(스토리 31) 질문이 폭주하고 흐름을 끊어 기각했다.
- 스킬 호출 시 남길지 먼저 묻기: 그리기 전엔 남길지 모르며, 폐기된 "남길지 먼저 정하라"로 회귀해 기각했다.
- 자동 스냅샷: 폐기된 "자동 보관"으로 회귀하고 동명 거부 정책과 충돌해 기각했다.
- 모델이 저장 여부를 기억: 컴팩션 뒤 유실·환각으로 기각했다.
- 캔버스 위 저장 라벨: 채팅 한 줄로 충분하다. 도그푸딩에서 "채팅을 안 본다"가 나오면 재고한다.

## Consequences

- 경로는 `export`·`import`가 돌려준 전체 경로를 적을 뿐 디스크를 스캔하지 않는다(2026-10-10, 구 "명령 인자 그대로" — 캔버스 서버의 cwd는 CLI·MCP 어느 쪽도 아니라 상대 경로로는 파일 없음을 확인할 수 없다). 기록은 세션 메모리에만 두고 스냅샷·export 파일에는 넣지 않는다. 경로가 없는 저장(`--out` 없는 `export`, JSON 문자열 `import`)은 기록하지 않는다.
- 파일은 클라이언트(MCP 프로세스·CLI 일회성 프로세스)가 쓰고 캔버스 서버는 요소를 건네줄 뿐이라(업스트림 구조) 서버는 저장이 있었는지 모른다. 그래서 `export`·`import`는 파일을 쓴 뒤 서버에 그림 id와 전체 경로를 알리고, 서버가 그 순간 요소를 기록한다(2026-10-10). 기각: 파일 쓰기를 서버로 옮기기(경로 기준이 CLI cwd·MCP 프로젝트 루트라 결국 클라이언트가 절대 경로를 알려 주는 모양이 되고, 이미 커밋된 export·import 전체가 이사함) / MCP 프로세스 메모리(다른 대화의 프로세스·다시 붙은 새 프로세스가 못 보고, 서버 안에서 처리되는 `snapshot save` 기록과 갈라짐). `export`는 파일에 넣으려고 읽은 요소를 함께 보내고 서버는 그것으로 기록한다 — 읽기와 알리기 사이에 브라우저에서 고친 것이 파일에 없는데 저장됨으로 찍히지 않게(2026-10-10). `import`는 막 놓인 복사본을 서버가 그 순간 기록한다. 알리기가 실패하면(예: 이 기능 전부터 떠 있던 옛 서버) 경고만 남기고 명령은 성공으로 끝난다 — 파일은 이미 써졌고, 기록이 없으면 미저장으로 보여 묻는 쪽이라 안전하다(2026-10-10). 같은 옛 서버는 `session list`에 수를 주지 못해 `null`로 나오고, 에이전트는 이때도 1회 묻는다(2026-10-10).
- "저장 후 수정됨"은 서버가 받을 때마다 붙이는 기록 칸을 뺀 모든 속성 비교다(2026-10-10). 브라우저를 클릭만 해도 전체 동기화가 와서 그 칸이 바뀌므로 글자 그대로 "어떤 속성이든"으로 하면 거짓 수정됨이 난다. 보이는 칸만 고르는 안은 목록에 없는 칸의 수정을 놓쳐 기각했다 — 거짓 경고의 비용은 질문 한 번, 놓침의 비용은 그림 유실.
- 크래시·재부팅으로 잃는 미저장 그림은 그대로 "버릴 그림"이다.

# 저장 상태는 서버가 계산해 screenshot 결과에 동봉하고, 스킬은 묻지 않고 옮겨 적는다

캔버스는 메모리라 브라우저 탭에 보여도 저장된 것이 아닌데, 사용자는 "이미 저장됐다"고 믿고 넘어가기 쉽다. 그래서 서버가 `export`·`import`·`snapshot save`가 지나갈 때 그림(frame)별 마지막 저장 경로·시각을 세션 상태에 적고, `screenshot` 결과에 그림별 상태(저장 경로 / 저장 후 수정됨 / 파일 없음 / 미저장, 마지막 스냅샷과 그 후 변경 여부)를 동봉한다. 스킬은 그림으로 답한 턴 끝에 그 값을 한 줄로 옮겨 적을 뿐 세거나 기억하지 않고, 저장할지 묻지 않는다. 사용자가 세션을 끝내자고 할 때 미저장·저장 후 수정된 그림이 있으면 그때 1회만 묻고 `session end`를 부른다. 결정론이 필요한 것은 모델이 아니라 서버가 맡는다는 원칙([ADR-0005](0005-server-checks-evidence-and-demotes.md)와 같은 이유)이다.

## Considered Options

- 그림마다 저장할지 묻기: 한 대화에 그림이 여럿이라(스토리 31) 질문이 폭주하고 흐름을 끊어 기각했다.
- 스킬 호출 시 남길지 먼저 묻기: 그리기 전엔 남길지 모르며, 폐기된 "남길지 먼저 정하라"로 회귀해 기각했다.
- 자동 스냅샷: 폐기된 "자동 보관"으로 회귀하고 동명 거부 정책과 충돌해 기각했다.
- 모델이 저장 여부를 기억: 컴팩션 뒤 유실·환각으로 기각했다.
- 캔버스 위 저장 라벨: 채팅 한 줄로 충분하다. 도그푸딩에서 "채팅을 안 본다"가 나오면 재고한다.

## Consequences

- 경로는 명령 인자로 받은 값을 적을 뿐 디스크를 스캔하지 않는다. 기록은 세션 메모리에만 두고 스냅샷·export 파일에는 넣지 않는다.
- 크래시·재부팅으로 잃는 미저장 그림은 그대로 "버릴 그림"이다.

# 캔버스는 지우지 않는다 — 불러오기는 얹고, 되돌리기만 지운다

업스트림은 캔버스 하나 = 그림 하나라서 `import --replace`와 ID 보존 merge, 전체 단위 restore로 충분했다. 우리는 한 캔버스에 그림 여러 개를 두고(스토리 17 before/after, 스토리 31 끌고 가기) 에이전트가 이전 그림을 뒤엎지 않아야 하므로, 에이전트는 캔버스를 지우거나 덮지 않고 새 그림을 새 frame으로 옆에 그린다. `import`는 캔버스를 지우지 않고 얹으며 요소·frame·바인딩 ID를 한 세트로 항상 새로 발급해 독립 복사본을 만든다(`--replace` 삭제). 캔버스를 비우는 명령은 `snapshot restore` 하나뿐이다. `clear`는 사용자 발화로만 부른다. 구 "clear·덮기 직전 자동 보관"은 출처 없는 발명이었고 이 규칙이면 지워지는 순간 자체가 없어 폐기했다 — 서버 크래시로 잃는 미저장 그림은 "기본 안 남김" 원칙상 버릴 그림이다.

## Considered Options

- 요소 ID 목록으로 저장·복사 범위 지정: 그림 경계 표현이 frame([ADR-0008](0008-frame-is-the-drawing-unit.md))과 이중이라 기각했다.
- 사용자가 브라우저에서 수동 복붙: 에이전트가 스토리 17을 못 하므로 기각했다.
- `import --mode replace|merge` 통합: 캔버스를 지우는지가 옵션 값에 숨어 기각했다.
- ID 보존 merge 유지: 원본이 캔버스에 있으면 덮어써 before/after가 하나로 합쳐져 기각했다.

## Consequences

- 불러온 그림은 현재 요소 전체 범위의 오른쪽에 `"<원본 이름> (복사)"` frame으로 놓는다. 파일에 frame이 없으면 파일명으로 frame 하나를 씌운다.
- 그림 사이 참조는 ID 재매핑에 포함해 복사본이 복사본을 가리키게 한다.

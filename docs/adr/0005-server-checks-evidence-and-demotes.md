# 근거는 서버가 존재만 검사하고, 틀리면 거부 대신 점선으로 강등한다

그림의 선·값에는 근거 태그(`코드`/`설계`/`로그`)를 붙인다. `코드` 태그의 `파일:줄`은 에이전트가 그릴 때마다 서버가 실제로 있는지 확인한다. 없거나 틀리면 그 선을 점선으로 내리고 캔버스에 "근거 없음: A→B"를 남긴다. 결정론이 필요한 검사는 모델 대신 서버 코드가 맡아, 약한 모델이 근거를 지어내도 그림에 드러나게 한다. 선이 정말 그 의존성을 뜻하는지는 검사하지 않고 에이전트가 판단한다. 서버는 선을 내리기만 하고 올리지는 않는다. `설계`·`로그` 태그는 검사하지 않고 기록만 한다. 근거 태그는 캔버스에 보이지 않는 요소 데이터이며, 사용자는 점선과 "근거 없음"만 본다.

## Considered Options

- archify처럼 근거가 틀리면 요소 생성을 거부: 그림이 안 나와 대화가 끊기고, 에이전트가 근거를 찾으러 혼자 재시도하는 루프가 생겨 기각했다.
- 저장(도면 승격) 시점에만 검사: 틀린 그림으로 나누는 대화는 저장 전부터 손해라 기각했다. 도그푸딩에서 매번 검사가 방해되면 다시 검토한다.
- 스킬 규칙으로 에이전트가 스스로 확인: 모델마다 지키는 정도가 달라 기각했다.

## Consequences

- 서버는 cwd를 레포 루트로 보고 경로를 푼다. 다른 폴더에서 띄우면 모든 `코드` 근거가 "근거 없음"이 된다.
- 요소 생성 경로(MCP create/batch, CLI `add`/`apply`)가 검사 함수 하나를 공유해야 한다. 새 생성 경로를 추가하면 검사도 같이 붙여야 한다.
- `설계`는 합의됐거나 논의 중인 계획·계약이다. 코드에 아직 없는 선(변경안, 마이그레이션 계획, 협의 중 API 계약)은 `설계` 태그로 그린다 — `코드` 태그면 선마다 "근거 없음"이 쌓여 그림이 온통 점선이 되기 때문. `설계` 선은 실선에 새 색이다.

# 근거는 서버가 존재만 검사하고, 틀리면 거부 대신 점선으로 강등한다

그림의 선·값에는 근거 태그(`코드`/`설계`/`로그`)를 붙인다. `코드` 태그의 `파일:줄`은 에이전트가 그릴 때마다 서버가 실제로 있는지 확인한다. 파일이 없거나 지정한 줄이 파일 범위 밖이면 그 선을 점선으로 내리고 캔버스에 "근거 없음: A→B"를 남긴다. 결정론이 필요한 검사는 모델 대신 서버 코드가 맡아, 존재하지 않는 파일·줄을 인용하면 그림에 드러나게 한다. 존재하는 줄을 잘못 인용한 의미 오류는 이 검사로 잡을 수 없다. 선이 정말 그 의존성을 뜻하는지는 검사하지 않고 에이전트가 판단한다. 서버는 에이전트가 처음부터 점선(추론)으로 그린 선을 실선으로 올리지 않는다. 서버 자신이 내린 선은 근거가 맞아지면 서버가 되돌린다 — 요소에 "서버 강등" 표시를 남겨 둘을 구분한다. (2026-09-14 검수 R04로 "내리기만 한다"를 이렇게 좁혔다) `설계`·`로그` 태그는 검사하지 않고 기록만 한다. 근거 태그는 캔버스에 보이지 않는 요소 데이터이며, 사용자는 점선과 `추론`·`근거 없음` 라벨을 본다.

2026-09-14 검수 R05: 점선은 확인되지 않음 전용으로 정한다. 추론은 `추론`, 서버 검사 실패는 `근거 없음` 라벨로 구분하고, 통신 방식은 화살촉과 라벨로 별도 표현한다. 구체 표기는 [PRD §3 "선 표기"](../../.scratch/archdraw-skill/spec.md)에 둔다.

## Considered Options

- archify처럼 근거가 틀리면 요소 생성을 거부: 그림이 안 나와 대화가 끊기고, 에이전트가 근거를 찾으러 혼자 재시도하는 루프가 생겨 기각했다.
- 저장(도면 승격) 시점에만 검사: 틀린 그림으로 나누는 대화는 저장 전부터 손해라 기각했다. 도그푸딩에서 매번 검사가 방해되면 다시 검토한다.
- 스킬 규칙으로 에이전트가 스스로 확인: 모델마다 지키는 정도가 달라 기각했다.

- 업스트림의 비동기·이벤트 점선 또는 UML의 응답 점선을 함께 사용: 확인된 통신도 불확실한 관계처럼 보여 기각했다. 응답 실선은 의도적인 표기 차이다(근거: [기존 조사 §4-3](../../.scratch/archdraw-skill/research-request.md)).

## Consequences

- 서버는 세션의 프로젝트 루트([ADR-0003](0003-one-canvas-server-per-session.md), `session start` 때 고정)를 기준으로 경로를 푼다. 프로젝트 루트가 잘못 잡히면 모든 `코드` 근거가 "근거 없음"이 되므로, `session start`는 잡은 루트를 출력하고 `--project`로 바로잡을 수 있다. (구 "cwd = 레포 루트"는 2026-09-14 검수 R03으로 대체)
- 근거가 캔버스에 들어오는 모든 경로(생성·수정·import·restore — MCP create/batch/update, CLI `add`/`apply`/`update`/`import`/`snapshot restore`, 서버 PUT)가 검사 함수 하나를 공유해야 한다. 새 경로를 추가하면 검사도 같이 붙여야 한다. 검사 통과는 파일·줄 존재만 뜻하며 실선이 코드 의존성을 보장하지 않는다 — 어제 스냅샷을 오늘 복원하면 사라진 근거는 그때 점선이 된다.
- "근거 없음: A→B" 텍스트는 원본 선의 부속물이다. 선 ID를 기억해 선이 움직이면 따라가고, 선이 삭제되거나 실선으로 복구되면 서버가 지운다. import로 복사할 때 ID 재매핑에 포함된다.
- `설계`는 합의됐거나 논의 중인 계획·계약이다. 코드에 아직 없는 선(변경안, 마이그레이션 계획, 협의 중 API 계약)은 `설계` 태그로 그린다 — `코드` 태그면 선마다 "근거 없음"이 쌓여 그림이 온통 점선이 되기 때문. `설계` 선은 실선에 새 색이다.

- 서버 강등·복구는 화살촉과 통신 방식·응답 라벨을 보존한다. 추론 라벨은 에이전트가 붙이며, 서버가 유효한 근거를 확인해도 추론 점선을 실선으로 올리지 않는다.

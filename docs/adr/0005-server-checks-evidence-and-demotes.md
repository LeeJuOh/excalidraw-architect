# 근거는 서버가 존재만 검사하고, 틀리면 거부한다

그림의 선·값에는 근거 태그(`코드`/`설계`/`로그`)를 붙인다. `코드` 태그는 파일 경로와 그 파일의 코드 글자(`quote`)를 적는다. 에이전트가 근거를 적거나 고칠 때 서버가 그 글자가 파일 안에 정확히 한 곳 있는지 확인한다. 공백(탭·공백·줄바꿈)의 차이는 무시한다. 없거나 여러 곳이면 서버는 그 요소를 만들지도 바꾸지도 않고 거부한다. 한 묶음(batch)에서 하나라도 틀리면 묶음 전체를 거부하고 틀린 것을 모두 나열한다 — frame 검사([ADR-0008](0008-frame-is-the-drawing-unit.md))와 같은 방식이다. 거부 에러는 고치는 길 두 개만 적는다: 맞는 글자로 고치기, 확인하지 못하면 `코드` 근거를 빼고 추론 점선으로 그리기. `설계`로 바꾸라고는 적지 않는다 — 검사를 피하는 길이 되어 확인되지 않은 실선이 생긴다. 서버는 선·박스의 모양을 바꾸지 않는다. 결정론이 필요한 검사는 모델 대신 서버 코드가 맡아, 존재하지 않는 코드를 인용하면 그 자리에서 막는다. 존재하는 글자를 잘못 인용한 의미 오류는 이 검사로 잡을 수 없다. 선이 정말 그 의존성을 뜻하는지는 에이전트가 판단한다. `설계`·`로그` 태그는 검사하지 않고 기록만 한다. 근거 태그는 캔버스에 보이지 않는 요소 데이터다.

(2026-10-11 개정. 구 "틀리면 점선으로 강등하고 근거 없음 텍스트를 남긴다. 근거가 맞아지면 서버가 되돌린다"(2026-09-14 검수 R04로 "내리기만"을 좁힌 것 포함). 강등·복구, "서버 강등" 표시, 선을 따라다니는 부속 텍스트, sync 뒤 정리, import ID 재매핑이 모두 이 규칙에서 나왔다. 07 착수 전 검수에서 태그를 바꿀 때의 전이처럼 정해지지 않은 경우가 계속 나왔다. 구 `파일:줄`은 커밋 고정 없이 지금 파일을 보므로 위에 줄이 끼면 낡아 `quote`로 바꿨다.)

2026-09-14 검수 R05: 점선은 확인되지 않음 전용으로 정한다. 통신 방식은 화살촉과 라벨로 별도 표현한다. 결정은 [PRD §3 "선 표기"](../../.scratch/archdraw-skill/spec.md)에, 보이는 라벨 문자열은 `docs/canvas-guide.md` 선 표기 표에 둔다(영어 고정, [ADR-0012](0012-canvas-labels-fixed-english.md)).

## Considered Options

- 틀리면 점선으로 강등(2026-09-14~10-10의 결정): 사용자가 에이전트의 첫 실수를 캔버스에서 본다는 장점이 있지만, 위 개정 메모의 장치가 모두 필요하고 정해지지 않은 전이가 계속 생겨 기각했다. 이 결정이 거부를 버린 이유("그림이 안 나와 대화가 끊기고, 에이전트가 혼자 재시도하는 루프")는 이렇게 푼다: 거부는 도구 호출 하나의 에러라 에이전트가 같은 턴 안에서 고치고, 에러가 추론 점선이라는 출구를 알려 루프를 끊는다.
- 저장(도면 승격) 시점에만 검사: 틀린 그림으로 나누는 대화는 저장 전부터 손해라 기각했다. 도그푸딩에서 매번 검사가 방해되면 다시 검토한다.
- 스킬 규칙으로 에이전트가 스스로 확인: 모델마다 지키는 정도가 달라 기각했다. 단, 복원 뒤의 알림은 이 방법에 기댄다(아래 Consequences).
- 커밋 고정(archify·Whiteboard): 근거가 "그 커밋에서 맞았나"를 뜻하게 된다. 우리는 지금 코드를 같이 보며 고치므로 "지금 맞나"가 필요하고, 커밋하지 않은 파일도 근거로 써야 해서 기각했다.
- 줄 번호(`line`): 커밋 고정 없이는 위에 줄이 하나만 끼어도 낡고, 낡은 번호가 다른 줄을 가리켜도 검사를 통과해 기각했다.
- `quote`의 최소 길이: 길이를 채우려고 관계없는 글자를 붙이게 되어 기각했다. "파일 안에서 한 곳" 규칙이 같은 일(너무 흔한 글자 막기)을 한다.
- 업스트림의 비동기·이벤트 점선 또는 UML의 응답 점선을 함께 사용: 확인된 통신도 불확실한 관계처럼 보여 기각했다. 응답 실선은 의도적인 표기 차이다(근거: [기존 조사 §4-3](../../.scratch/archdraw-skill/research-request.md)).

## Consequences

- 서버는 세션의 프로젝트 루트([ADR-0003](0003-one-canvas-server-per-session.md), `session start` 때 고정)를 기준으로 경로를 푼다. 경로는 루트 기준 상대 경로이며, 루트 밖(`..`, 절대 경로)과 `.git`은 거부한다(archify와 같은 규칙). 프로젝트 루트가 잘못 잡히면 모든 `코드` 근거가 거부되므로, `session start`는 에이전트가 넘긴 경로에서 루트를 찾고 잡은 루트를 출력한다(2026-10-05, 구 "`--project`로 바로잡을 수 있다"). (구 "cwd = 레포 루트"는 2026-09-14 검수 R03으로 대체)
- 에이전트가 근거를 적거나 고치는 모든 쓰기(MCP create/batch/update, CLI `add`/`apply`/`update`)가 검사 함수 하나를 공유한다. 새 경로를 추가하면 검사도 같이 붙여야 한다. 근거를 건드리지 않는 쓰기(위치·색만 바꾸기)와 브라우저 sync는 검사하지 않는다 — 브라우저에는 근거를 고치는 UI가 없고, 옮기기만 했는데 거부되면 안 된다. (2026-10-11 개정, 구 "`evidence` 칸이 바뀌면 sync를 포함해 어디서든 검사")
- 브라우저 sync는 근거를 쓰지도 않는다. 서버는 브라우저가 보낸 `evidence`를 무시하고, 같은 id에 이미 있던 근거를 유지한다. Excalidraw의 요소 변환이 모르는 키를 버려 브라우저를 한 번 거치면 근거가 지워지기 때문이다. 브라우저에서 복제·붙여넣기로 생긴 요소는 새 id라 근거가 없다 — 복사본이 원본의 근거를 검사 없이 달고 다른 선이 되는 일을 막는다. 남은 한계: 브라우저에서 지우고 sync한 뒤 실행 취소로 살린 요소는 근거를 잃는다. 지운 요소의 근거까지 기억하면 에이전트가 같은 id로 새 요소를 만들 때 옛 근거가 붙어 기각했다. (2026-10-12, 07 슬라이스 C)
  - 기각: 프론트가 변환 뒤 `evidence`를 다시 붙이기 — 복제본이 근거를 달고 나간다. `customData.evidence`로 옮기기 — 서버·`describe`·스냅샷 모양이 모두 바뀐다.
- import·`snapshot restore`는 거부하지 않는다. 거부하면 복원 자체가 안 되기 때문이다. 받아들이고, 결과에 근거 없음 요소의 목록을 돌려준다. 그림은 바꾸지 않는다. 에이전트는 같은 코드를 다른 곳에서 찾으면 근거를 고치고 사용자에게 알리며, 찾지 못하면 그 관계가 코드에서 없어졌는지 사용자에게 묻는다(스킬 규칙). 이 경로만 스킬 준수에 기대므로, 에이전트가 목록을 알리는지 02 도그푸딩에서 본다.
- 검사 통과는 "지금 파일에 그 글자가 한 곳 있다"만 뜻하며 실선이 코드 의존성을 보장하지 않는다. 거부를 피하려고 관계없는 글자를 베끼면 통과한다 — 02 도그푸딩에서 본다.
- `설계`는 합의됐거나 논의 중인 계획·계약이다. 코드에 아직 없는 선(변경안, 마이그레이션 계획, 협의 중 API 계약)은 `설계` 태그로 그린다 — `코드` 태그면 선마다 거부되기 때문. `설계` 선은 실선이고, 변경안의 요소는 변경 상태 색을 쓴다([ADR-0015](0015-color-only-for-change-status.md)).
- 박스에도 `코드` 태그가 붙을 수 있고(초안 시작 장면, 스토리 33) 같은 규칙으로 검사한다.
- 추론 점선과 추론 라벨은 에이전트가 그린다. 서버는 모양을 바꾸지 않으므로, 유효한 근거를 확인해도 추론 점선을 실선으로 올리지 않는다.

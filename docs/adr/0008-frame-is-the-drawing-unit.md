# 그림 하나 = frame 하나

캔버스에 그림 여러 개가 놓이므로([ADR-0007](0007-canvas-never-cleared-import-copies.md)) 저장·복사·탐색·과밀 세기의 단위가 필요하다. Excalidraw의 `frame` 요소를 그림 단위로 쓴다. frame 이름이 그림 제목(답하는 질문)이고, `export --frame`, `describe`의 그림별 묶음, "한 그림에 한 종류" 판정, "안 그림" 줄 위치, 사용자가 frame을 끌면 그림 통째 이동이 전부 frame에 의존한다. 그림 참조는 frame 이름이 아니라 ID 기반이다 — 이름 변경·복사에 견뎌야 하고, 일부만 export한 파일의 미포함 참조가 이름이 같은 다른 그림에 붙으면 안 되기 때문이다. ID는 박스 요소의 `link` 칸에 Excalidraw 요소 링크 `?element=<frame id>`로 적는다(2026-09-20). 에이전트가 읽는 데이터이면서 브라우저에서 박스의 링크 아이콘을 누르면 캔버스가 같은 탭에서 그 frame으로 이동한다. 이 이동은 프론트가 `onLinkOpen`으로 구현한다(2026-10-06, 코드 확인 뒤 정정): Excalidraw 0.18.1의 `isElementLink`는 `new URL()`로 주소를 읽어 상대 주소 `?element=…`를 요소 링크로 인식하지 못하고 새 탭을 연다. 구현 없이 생기지 않는다. 프론트를 고치지 않고 클릭 인수를 지우는 안은 링크 아이콘이 그대로 남아 누르면 같은 캔버스가 새 탭에 열려 깨진 것처럼 보이므로 기각했다. 업스트림에는 `frameId` 칸만 있고 frame 타입이 없어 서버에 추가한다. frame 자체는 Excalidraw 0.18이 원래 그리므로 프론트 수정이 없다.

## Considered Options

- group + 제목 텍스트: 경계 상자가 없어 과밀 세기·frame 끌기·`export --frame`을 따로 구현해야 해 기각했다.
- 그림 참조를 frame 이름으로: 복사본 `"(복사)"`와 동명 그림에서 대상이 갈려 기각했다.
- 그림 참조를 `customData`에: 화면에 안 보이고 다른 칸과 겹치지 않지만 클릭 탐색이 생기지 않는다. 코드 위치는 근거 태그가 이미 가져 `link` 칸이 비어 있으므로 기각했다.

## Consequences

- 서버가 frame을 만들거나 자식을 넣을 때 자식이 경계 밖이면 frame을 키운다(줄이지 않고 자식은 옮기지 않음). Excalidraw가 밖으로 나간 자식을 잘라 그려 스크린샷에서 안 보이기 때문이다. 서버 경로로 자식의 위치·크기를 바꿀 때도 같다. 키울 때만 여백 40을 두고, 이미 안에 있는 자식 때문에 frame을 바꾸지 않는다. 크기 없이 만든 frame은 서버가 자식 범위 + 여백으로 정한다(2026-10-05).
- 서버 경로로 frame을 지우면 자식도 같이 지운다(2026-10-05). frame만 지울 경우가 없고, 남은 자식이 없는 frame을 가리키면 화면이 씬 갱신을 거부한다. 자식을 남기고 `frameId`만 비우는 안은 어느 그림에도 속하지 않는 요소를 만들어 기각했다. 서버는 묻지 않고, 미저장 그림을 지우기 전에 묻는 것은 스킬이다([ADR-0010](0010-server-reports-save-state-skill-never-asks.md)).
- `--frame`으로 일부만 export하면 파일 밖 대상을 가리키는 참조는 미포함으로 남고, import 뒤 어떤 그림에도 붙지 않는다.

# 색은 변경 상태에만 쓴다

그림의 색은 **변경 상태 색** 세 개 — 새로 생김(초록), 변경안에서 없앨 것(빨강), 수정됨(노랑) — 에만 쓰고, 나머지는 흰 박스와 검정 선으로 그린다(2026-10-02 결정). 업스트림 캔버스 가이드는 서비스·큐·DB 같은 요소 종류와 주 경로·성공·실패에 색을 주었고, 기존 PRD는 레이어 의존 방향 위반을 빨강으로 표시하게 했다. 이 프로젝트의 그림은 구현 전에 사용자가 에이전트의 오해를 잡는 수단이므로 한눈에 보여야 하는 것은 "무엇이 바뀌는가"다. 색 하나가 여러 뜻을 가지면 빨강 박스가 실패인지 없앨 것인지 읽을 수 없고, 사용자가 같은 색으로 칠한 편집의 뜻도 정할 수 없다.

## Considered Options

- 종류 색은 채우기로 두고 변경 상태는 테두리로만 표시: 캔버스에서 같은 박스로 비교한 뒤 기각했다. 바뀐 곳이 덜 보이고, 모듈 구분은 경계 박스로 충분하다.
- 레이어 의존 방향 위반을 빨강으로 표시: 외부 출처를 찾지 못했고 빨강의 뜻과 충돌해 기각했다. 위반인지는 에이전트가 판단하지 않는다. 에이전트는 코드의 의존을 그대로 그리고, 사용자가 그림을 보고 판단한다.
- Excalidraw 색 선택 도구의 기본 버튼에 있는 진한 채우기: 같은 경로 그림으로 비교한 뒤, 라이트 모드에서 연한 채우기가 더 읽기 좋아 기각했다.

## Consequences

- 실패는 색이 아니라 검정 선과 상태 코드 글자로 나타낸다.
- 바뀐 박스는 연한 채우기와 같은 계열 테두리에 고정 영어 라벨을 붙인다. 색을 구분하기 어려운 사용자도 뜻을 읽을 수 있어야 한다. 라벨을 영어로 고정하는 이유는 [ADR-0012](0012-canvas-labels-fixed-english.md)와 같다.
- 바뀐 화살표에는 초록·빨강만 쓴다. 이름만 바뀌어도 옛 화살표를 빨강으로 남기고 새 화살표를 초록으로 더한다. 노랑은 박스가 남고 안에서 하는 일이 바뀔 때만 쓴다.
- 계약 메모지의 연한 회색 배경은 뜻이 없는 배경이며 이 규칙의 예외가 아니다(2026-10-04). 노랑 메모지는 수정됨과 충돌해 쓰지 않는다. 변경안에서 계약이 새로 생기거나 바뀌면 메모지 배경도 변경 상태 색을 쓴다.
- 사용자가 색을 요청하면 에이전트는 세 색을 빼고 고른다. 요청이 세 색의 뜻과 충돌하면 이유를 한 줄로 말하고 다른 색을 제안한다.
- 색값과 라벨 문자열의 원본은 [ADR-0006](0006-canvas-guide-single-source-via-mcp.md)대로 `docs/canvas-guide.md` 한 곳이다. 업스트림 머지로 종류 색이 되살아나면 지운다.
- 다크 모드에서 연한 채우기가 배경과 구분되는지는 확인하지 않았다.

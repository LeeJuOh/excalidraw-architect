# 다섯 줌 레벨은 고정 포함 트리가 아니라 안내 체계다

시스템 컨텍스트(L1) / 배포 단위(L2) / 모듈 경계(L3) / 레이어(L4) / 경계 타입(L5) 이름과 허용 디테일을 유지하되, 실제 코드 구조에 따라 중복 단계를 생략하고 공용 모듈 그림을 함께 참조한다. 모듈 자체가 레이어이거나 여러 배포 단위가 같은 모듈을 쓰면 고정 포함 트리가 구조를 왜곡하기 때문이다. 2026-09-14 검수 R06 합의로 기존의 “각 그림은 윗 박스 하나의 확대”와 DDD 일대일 매핑을 수정했다.

## Considered Options

- C4 이름을 그대로 사용: 백엔드 실무의 모듈 경계를 별도로 안내하려는 목적과 맞지 않아 기존 이름을 유지한다.
- 다섯 단계를 반드시 순서대로 확대: 레이어별 모듈에서 같은 내용을 반복하므로 기각했다.
- 공용 모듈 내부 그림을 배포 단위마다 복제: 동일한 내부 설명이 갈라지므로 기각했다. 사용 관계는 각 배포 단위 그림에 표시하고 내부 그림 하나를 함께 참조한다.
- 바운디드 컨텍스트를 L2 또는 L3 박스 하나와 동일시: 실제 도메인 경계가 배포·모듈과 항상 일치하지 않아 기각했다.

## Consequences

- 기능별 모듈은 모듈 내부 레이어를 확대한 뒤 경계 타입으로 내려간다. 모듈 자체가 레이어이면 별도 레이어 그림 없이 경계 타입으로 내려간다.
- 바운디드 컨텍스트는 실제 코드·설계대로 표시한다. 박스와 일치하면 이름, 박스 내부에 여러 개면 내부 경계, 여러 박스에 걸치면 묶는 경계를 사용한다. 컨텍스트 사이 관계와 배포 단위 사이 연결을 동일시하지 않는다.
- 한 그림의 레벨과 허용 디테일은 유지한다. 단계 생략이 상위 그림에 하위 디테일을 섞는 허가는 아니다.
- 공유 참조와 단계 생략은 파일명에 반영하지 않는다 — 구 "줌 경로가 파일명" 규칙은 폐기했고 저장 경로·파일명은 사용자 지정 또는 에이전트 선택이다(2026-09-16, 검수 R07). 그림 사이 참조는 frame 이름이 아니라 ID 기반이다([ADR-0008](0008-frame-is-the-drawing-unit.md)). 그림 선택 규칙과 예시 검증은 03 스킬 본문 이슈가 맡는다.

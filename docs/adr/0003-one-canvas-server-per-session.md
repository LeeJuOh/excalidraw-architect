# 에이전트 세션 하나에 캔버스 서버 하나

업스트림은 머신당 캔버스 서버 하나(포트 3000)라서, 동시에 작업하는 에이전트 세션들이 캔버스 하나를 나눠 쓴다. 우리는 `session start`가 빈 포트에 서버를 따로 띄우고 세션 키를 발급하게 한다. CLI 폴백에서는 이후 호출에 `--session <키>`를 붙인다. MCP 경로([ADR-0002](0002-cli-first-via-skill-shim.md), 2026-09-20 개정)에서는 호스트가 에이전트 세션마다 MCP 프로세스 하나를 띄우므로 에이전트가 `session_start` 툴에 프로젝트 경로를 넘기면 그 프로세스가 캔버스 세션 하나를 새로 띄워 붙는다(2026-10-05 개정, 구 "첫 툴 호출 때 자동"). 그리는 툴은 키도 경로도 받지 않고, 붙기 전에 부르면 `session_start`를 안내하는 에러를 낸다. 같은 프로젝트에 살아 있는 캔버스 세션이 이미 있으면 새로 띄우기 전에 그 목록을 사용자에게 한 줄 알리되 묻지 않으며, 사용자가 말하면 `session_attach`로 그것에 붙는다 — 새 에이전트 세션이 압도적으로 잦고(동시 작업이 이 결정의 이유), 어제 캔버스 재개는 사용자가 말로 고른다. CLI 폴백에서 캔버스를 쓰는 명령은 `--session <키>`를 반드시 받고, 없으면 살아 있는 캔버스 세션의 목록(키, 프로젝트 루트)을 담은 에러를 낸다(2026-10-05 개정. 구 "키를 생략하면 하나일 때 그 세션으로"(2026-09-19 2차 검수 A6)는 cwd로 프로젝트를 알던 때의 편의 규칙이다. cwd를 쓰지 않으면 머신 전체에서 세야 하고, 다른 프로젝트의 캔버스에 에러 없이 그리게 된다). 컴팩션으로 키를 잃으면 에이전트가 `session list`에서 자기 프로젝트의 캔버스 세션을 고른다 — 하나면 그것으로 돌아가고 여럿이면 사용자에게 묻는다. 키는 서버가 발급하며 호스트의 세션 ID나 PPID에 의존하지 않으므로, Claude와 Codex에서 똑같이 동작한다. 캔버스 세션은 사용자의 `session end`로 끝나거나, 연결이 0개인 상태(붙은 MCP 프로세스 없음, 열린 브라우저 탭 없음)가 30분 이어지면 캔버스 서버가 스스로 끝낸다. 타이머는 캔버스 서버가 가진다 — MCP 프로세스가 강제 종료돼도 동작해야 하기 때문이다. 기준은 "활동 없음"이 아니라 "연결 없음"이다: 탭을 열어 두고 생각하는 동안에는 끝나지 않는다. 이때 저장하지 않은 그림은 없어지는데, 설명 그림은 버리는 것이 기본이고 남길 그림은 승격해 파일로 둔다. (2026-10-05 개정. 구 "끝내는 방법은 `session end` 하나뿐, 자동 감지 없음"은 CLI가 기본이던 때의 결정이다. 그대로 두면 사용자가 에이전트 세션을 그냥 닫을 때마다 캔버스 서버가 쌓인다.)

세션은 시작 시점에 프로젝트 루트(에이전트가 넘긴 경로에서 위로 올라가 찾은 git 루트, 없으면 그 경로)를 고정해 가진다. CLI 폴백의 `session start`는 `--project <경로>`를 반드시 받고, 없으면 에러를 낸다 — cwd에서 추측하면 틀려도 에러가 없기 때문이다(2026-10-05 개정, 구 "cwd에서 찾고 `--project`로 덮어쓰기 가능"). 이후 호출은 세션 키만으로 같은 프로젝트를 가리키므로, 하위 폴더나 스킬 폴더에서 불러도 근거 경로와 프로젝트별 스냅샷 저장소가 어긋나지 않는다. 산출물 export 경로는 사용자가 지정하거나 에이전트가 선택하며, 프로젝트 루트 고정이 산출물 저장 폴더를 제한하지는 않는다(2026-09-16 명확화). MCP 툴에 상대 경로가 오면 프로젝트 루트 기준으로 푼다 — MCP 프로세스의 cwd는 호스트마다 달라 사용자가 모르고, 에이전트가 "프로젝트의 문서 배치"를 보고 경로를 정하기 때문이다. CLI는 cwd 기준이다(2026-10-09). (2026-09-14 추가, 검수 R03)

MCP 경로에서는 두 호스트 모두 에이전트가 `session_start`의 인자로 프로젝트 경로를 넘기고, 서버가 그 경로에서 위로 올라가 git 루트를 찾는다. MCP 프로세스의 cwd는 쓸 수 없다 — Codex는 플러그인 루트에서 프로세스를 띄운다([ADR-0011](0011-plugin-lives-under-plugin-dir.md)). MCP `roots/list`도 쓰지 않는다 — Claude Code 2.1.289는 세션 폴더를 답하지만 Codex 0.160.0은 빈 목록을 답한다(2026-10-05 실측). 호스트마다 다른 입력을 쓰는 것보다 규칙 하나를 택했다. CLI 폴백의 `session start`와 모양이 같아진다. (2026-10-05 추가)

업스트림의 "머신당 서버 하나" 코드는 남기지 않는다: CLI `start`/`stop`/`status`, `--url`·`EXPRESS_SERVER_URL`, `EXCALIDRAW_NO_AUTOSTART`, 포트별 pid 파일, 첫 사용 때의 자동 시작, `screenshot` 전에 모든 탭을 다시 적재시키던 `initial_elements` 재방송(2026-10-10 추가. 탭 여럿의 사본을 맞추는 용도였고 재적재가 저장 상태를 깨뜨렸다 — [ADR-0010](0010-server-reports-save-state-skill-never-asks.md). 탭 수는 제한하지 않는다. 탭 둘을 열면 한 탭의 손 편집이 다른 탭에 가지 않는 업스트림 빈틈은 그대로라, 새로고침하지 않은 탭이 `screenshot`에 옛 그림을 낼 수 있다. 새로고침하면 풀린다. 손 편집 동기화는 후속 이슈), vite 개발 서버가 포트 3000으로 넘기던 프록시(2026-10-09 추가. 캔버스 서버가 3000에 없어 이미 닿지 않았다. `npm run dev`는 프론트를 다시 빌드하는 watch로 바꾸고, 확인은 세션 캔버스 탭을 새로고침한다). 남기면 키·프로젝트 루트·기록·자동 종료가 없는 캔버스 서버를 띄우는 두 번째 방법이 생긴다. 살아 있는 캔버스 세션의 기록은 `~/.excalidraw-architect/sessions/<키>.json`에 캔버스 서버마다 파일 하나로 둔다 — 파일 하나에 전부 두면 동시에 시작한 두 서버가 서로의 줄을 지울 수 있다. 대가는 업스트림 머지의 충돌과, 다른 머신의 캔버스 서버에 붙는 기능을 잃는 것이다. (2026-10-05 추가)

붙어 있던 캔버스 세션이 끝난 뒤(`session_end` 뒤, 또는 캔버스 서버가 죽은 뒤)에 그리는 툴을 부르면 에러다. 붙기 전의 에러와 같고, 새 캔버스 서버를 자동으로 띄우지 않는다 — 포트가 달라져서 사용자의 브라우저 탭은 죽은 주소에 남고, 에이전트는 새 URL을 알릴 계기가 없다. 업스트림은 툴 호출마다 다시 띄우는데, 주소가 포트 3000으로 고정이라 가능한 방식이다. `session_end`는 키를 받는다: 키가 없으면 자기가 붙은 캔버스 세션을, 키가 있으면 그 캔버스 세션을 끝낸다. 새 에이전트 세션에서 어제의 캔버스 세션을 끝낼 방법이 필요하기 때문이다. 키로 끝내는 것은 사용자가 말했을 때만 한다. (2026-10-05 추가)

대화를 새로 시작하는 명령과 MCP 프로세스(2026-10-05 실측): Claude Code 2.1.289의 `/clear`는 MCP 프로세스를 다시 시작하지 않아서 같은 캔버스 세션을 계속 쓴다. Codex 0.160.0의 `/new`("Current checkout")와 `/clear`는 새 MCP 프로세스를 바로 띄우고 이전 것을 약 1분 뒤에 끝낸다(`/new` 두 번: 16~97초 사이, 57~62초 사이. `/clear` 한 번: 57~62초 사이). 그래서 Codex에서는 `/new`·`/clear` 뒤에 에이전트가 `session_start`를 다시 부르고, 이전 캔버스 세션은 탭이 닫혀 있으면 그 약 31분 뒤에 스스로 끝난다. 호스트를 구분하는 코드는 없다.

## Considered Options

- 프로젝트 경로별 포트: 같은 폴더에서 연 여러 세션을 나눌 수 없어 기각했다.
- 서버 하나에 세션별 frame: 캔버스를 분리하고 싶을 때 코드가 두 벌 필요해 기각했다.
- MCP 프로세스가 같은 프로젝트의 살아 있는 캔버스 하나에 자동으로 붙기: 같은 폴더에서 연 두 번째 에이전트 세션이 첫 세션의 캔버스에 붙어 버려 이 결정의 이유(동시 작업 분리)를 깬다. 기각하고 "기본 새로, 말하면 붙기"를 택했다.
- Claude Code에서는 `roots/list`로 받고 Codex에서만 에이전트가 넘기기: Claude Code에서 호출이 줄지만 코드 경로와 스킬 지시가 호스트마다 갈려서 기각했다(2026-10-05).
- 자동으로 끝내지 않기(구 결정): 캔버스 서버가 쌓여서 기각했다(2026-10-05).
- 에이전트 세션이 끝나면 바로 끝내기: 호스트를 실수로 닫으면 그림을 잃고, 다음 날 이어서 그릴 수 없어 기각했다(2026-10-05).
- CLI의 `session start`가 cwd에서 프로젝트 루트를 추측(구 결정): 에이전트의 cwd가 프로젝트 밖이면 틀린 루트가 에러 없이 저장돼서 기각했다(2026-10-05).
- 키 없는 CLI 호출은 살아 있는 캔버스 세션이 하나일 때 그것으로(구 결정): cwd를 쓰지 않으면 머신 전체에서 세야 하고, 다른 프로젝트의 캔버스에 에러 없이 그려서 기각했다(2026-10-05).
- 캔버스 세션 기록을 파일 하나(`sessions.json`)에: 동시에 시작한 두 캔버스 서버가 서로의 줄을 지울 수 있고 잠금 코드가 필요해서 기각했다(2026-10-05).
- 기록 없이 프로세스 목록(`ps`)에서 찾기: 포트·키·프로젝트 루트가 없고 OS마다 명령이 달라서 기각했다. 기록이 살아 있는지 검사하는 데만 쓴다(2026-10-05).
- 업스트림의 `start`/`stop`/`status`와 `EXPRESS_SERVER_URL`을 함께 남기기: 업스트림 머지의 충돌은 줄지만 캔버스 서버를 띄우는 방법이 둘이 돼서 기각했다(2026-10-05).
- 붙은 캔버스가 없어지면 새 캔버스 서버를 자동으로 띄우기(업스트림 방식): 사용자의 탭과 에이전트가 그리는 캔버스가 갈려서 기각했다(2026-10-05).
- CLI 기본 유지(구 2026-09-11): [ADR-0002](0002-cli-first-via-skill-shim.md) 2026-09-20 개정으로 MCP 우선이 됐다. 키·`--session`은 CLI 폴백에서만 보인다.
